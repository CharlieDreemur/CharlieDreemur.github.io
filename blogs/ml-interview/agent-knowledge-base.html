先弄清楚：每个概念是什么

Knowledge base
agent 动手前查的资料库。FlashVector 的分两部分，人维护的文档和 agent 写回的状态。
Per-model card
每个模型一张，记上次 run 的结论。Figure 2 的图中文字是 "each run starts from the last run's findings"。
Refine
四步循环之外的一步。整个 run 结束后执行一次，把结果写回 knowledge base。
In-place 更新
改写原有的条目，不在末尾追加。像病历首页，每次就诊只更新当前诊断。

看图：谁写，什么时候取和写回

30 秒回答

I'd split it into docs that humans curate and state that the agent writes back. FlashVector has six doc categories, from business logic to an optimization cookbook, plus a per-model card. At the start of a run the agent retrieves only the docs for the layer it is working on. At the end it updates the card in place with what was accepted and what was rejected, so the next run starts from conclusions and the memory stays bounded. The risk is that a wrong conclusion keeps misleading later runs, so write-backs should carry evidence and get reviewed.

FlashVector 怎么取，怎么写回

环节做法
人写什么六类文档：Business Logic、Model Server、Feature Store、ML Model、Hardware、Optimization Cookbook（专家总结的优化规则）
怎么取run 开始时取 serving layer 对应的文档；Diagnose 只拿被抽中那一层的
写回什么接受和拒绝的改动、run summary、verify 接受的容差阈值
怎么写Refine 做 in-place 更新，不追加，所以 memory 有上限

拒绝的改动也记，下次 run 就不会再试同一个失败方案。论文说 in-place 更新 "bounds the amount of memory the agent maintains"，还能减轻 "catastrophic forgetting and hallucinations"。

共同点是 memory 只存结论，失败也要记。

必答点

  • knowledge base 分两部分：人维护的六类文档，agent 写回的 per-model card
  • 取：只取当前这一层的文档
  • 写回：run 结束后 Refine 做 in-place 更新，memory 有上限
  • 接受的和拒绝的改动都记
  • 风险：写错的结论会一直误导后面的 run，要带证据并有人 review
  • 存储、检索、review、回滚、并发写，论文都没写

追问

agent 把一个错的结论写进了 card，会怎样？

后面每次 run 都从这个结论出发，一直被误导。所以每条写回要带证据并有人 review。

几个 run 同时写同一张 card 怎么办？

论文没写。我会给 card 加版本号，写之前比对版本，变了就重读再合并，和 edit tool 的 hash 检查同理。

模型或硬件换了，card 里的旧结论还能用吗？

论文没写旧结论怎么失效。我会让每条结论带上当时的 release 和硬件，对不上的就重新 verify。
