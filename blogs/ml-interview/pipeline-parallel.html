Pipeline Parallel：bubble 怎么来、多大？
1F1B、interleaved 解决什么？peak memory 一样吗？

英文问法Where does the pipeline bubble come from and how big is it? · GPipe vs 1F1B? · How does the interleaved schedule shrink the bubble, and at what cost? · Is peak memory the same with and without PP?

先弄清楚：每个概念是什么

Pipeline parallel（PP）
把 \(L\) 层按顺序切成 \(p\) 段（stage），每张卡一段，像流水线上每个工位只装一部分。相邻 stage 之间 p2p 传 activation（backward 传 gradient）。例：L = 32、p = 4 → 每卡 8 层，参数和 optimizer state 每卡 1/4。
Micro-batch
一个 batch 切成 \(m\) 份依次送进流水线。第 1 份到 stage 2 时，stage 1 已经在算第 2 份，多个工位才能同时干活。
Pipeline bubble
开工时后面的 stage 在等上游的 activation，收工时前面的 stage 在等下游的 gradient，这段空转就是 bubble。为了 optimizer 语义严格同步，每个 batch 末尾都要 flush 一次，所以每个 batch 都有。
1F1B
先做几个 forward 预热，之后做一个 forward 就做一个 backward，backward 完就释放那份 activation。像洗碗洗一个放一个，不攒一池子。
Interleaved 1F1B
每张卡拿 \(v\) 段不相邻的层，每段更短，流水线填满和排空更快。例：16 层、p = 4、v = 2：GPU0 拿第 1–2 层和第 9–10 层。

30 秒回答

Pipeline parallelism splits the layers into p stages on p GPUs and the batch into m micro-batches. At the start later stages wait for activations, and at the end earlier stages wait for gradients; that idle time is the bubble, (p−1)/m of the ideal compute time for both GPipe and 1F1B, so we want m ≫ p. GPipe runs all forwards before any backward, so it stashes activations for all m micro-batches; 1F1B alternates one forward and one backward after a warm-up, so at most p are in flight. The interleaved schedule gives each GPU v non-contiguous chunks, cutting the bubble to (p−1)/(vm) at v times the point-to-point communication.

推导 / 关键公式

bubble 多大

开头空等 \(p-1\) 个 forward，结尾空等 \(p-1\) 个 backward：

\[ t_{pb} = (p-1)(t_f+t_b),\qquad t_{id} = m\,(t_f+t_b) \] \[ \text{bubble} = \frac{t_{pb}}{t_{id}} = \frac{p-1}{m} \]

interleaved

每段的 forward、backward 时间都变成 \(1/v\)，bubble 跟着 \(\div v\)，但 stage 之间的 p2p 通信 \(\times v\)；要求 \(m\) 是 \(p\) 的整数倍：

\[ \text{bubble}_{\text{int}} = \frac{1}{v}\cdot\frac{p-1}{m} \]

peak activation（第一个 stage 最大）

GPipe 存 \(m\) 个 micro-batch。1F1B 存 \(p\) 个，每个 \(L/p\) 层，合计 \(L\) 层的量，和不切 PP 一样，不随 \(p\) 变小。interleaved 再乘 \(1 + \frac{p-1}{pv}\)。

必答点

  • bubble 来自流水线的填充和排空：\((p-1)/m\)，GPipe 和 1F1B 一样 → 要 \(m \gg p\)
  • 1F1B 不减 bubble，减 memory：in-flight \(\le p\)（GPipe 是 \(m\)）
  • interleaved：bubble \(\div v\)，代价是 p2p 通信 \(\times v\)
  • peak memory 不一样：model state 每卡 \(1/p\)；activation 第一个 stage 最多（\(L\) 层 × 1 份），最后一个最少

追问

(p−1)/m 是占什么的比例？

占理想计算时间 \(t_{id}\)。占总 wall time 是 \((p-1)/(m+p-1)\)：\(p = 8\)、\(m = 32\) 时是 7/39 = 17.9%。GPipe 论文的经验是，\(m \ge 4p\) 时 bubble 可以忽略。

m 越大越好吗？

global batch 固定时，\(m\) 大意味着 micro-batch 小，GEMM 的 arithmetic intensity 变低。时间约 \((m + p - 1)\,(t_f(b) + t_b(b))\)，要在 bubble 和单卡效率之间取最优 \(b\)（Megatron 论文里的 GPT 例子是 \(b = 4\)）。

Zero Bubble 怎么做到的？

把 backward 拆成 B（对输入的 gradient，上一个 stage 在等）和 W（对 weight 的 gradient，没人等），W 往后挪去填 bubble。再绕开 optimizer step 的全局同步，在同步训练语义下做到零 bubble。

DualPipe 是什么？

DeepSeek-V3 的 schedule：micro-batch 从流水线两端同时喂；把一对 forward、backward chunk 拆成 attention、all-to-all dispatch、MLP、all-to-all combine 交错执行，让 MoE 的 all-to-all 和 PP 通信被计算盖住。代价是每卡存两份参数，activation peak 多约 \(1/p\)。

串行的几张卡负载不均怎么办？

先加大 \(m\)、用 interleaved 或 Zero Bubble 减 bubble。第一个 stage 有 embedding、最后一个有 LM head 和 loss，给它们少放几层（Megatron：--decoder-first-pipeline-num-layers、--decoder-last-pipeline-num-layers）。
