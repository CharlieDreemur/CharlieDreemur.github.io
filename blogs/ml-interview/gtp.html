Generalized Tensor Parallelism（GTP）是什么？
它和 TP、ZeRO-3 差在哪，all-gather 怎么藏？

英文问法What is Generalized Tensor Parallelism in Megatron Core? · How does GTP_remat differ from TP, and from ZeRO-3 on the data-parallel axis? · How does GTP hide the weight all-gather behind compute, and what happens to the weight gradient?

考过推断，非面经，题目是按团队自己的 GTP 文档和 release notes 推断的

先弄清楚：每个概念是什么

GTP_remat
把 TP 切完的那片 weight 再切一次，每卡平时只存一小片。GEMM 之前用 all-gather 拼回完整的 TP slice，算完就释放。remat 来自 rematerialize。
Prefetch chain
weight 按 forward 的顺序连成一条链。算当前层时，提前把下一层的 all-gather 发出去。
Deferred finalize
weight gradient 的 reduce-scatter 的结果推迟一步才并进 main_grad。这里的一步是 backward 往前走一层，不是一个 training step。

看图：all-gather 和上一层的 GEMM 同时跑

30 秒回答

GTP equals TP times GTP_remat. TP keeps each weight split through the GEMM. GTP_remat splits the TP slice again: each rank keeps one shard, rebuilds the full slice with an async all-gather right before the GEMM, and frees it afterwards. The doc calls it an implementation of ZeRO-3 that shards along a model-parallel axis, not the data-parallel one, and materializes one weight at a time, not a bucket. Each layer's all-gather is prefetched during the previous layer's GEMM, so all but the first are hidden. Weight gradients return through an async reduce-scatter whose finalize is deferred one step. It's still experimental.

文档说 "GTP_remat is an implementation of ZeRO-3"（ZeRO-3 见 DP、ZeRO、FSDP），区别是表里“沿哪个轴切”和“粒度”两行，所以每个 weight 可以单独 prefetch。“TP 切计算、传 activation，GTP_remat 只切存储、传 weight”是按这张表推断的。TP 本身怎么切见 TP Linear。

每卡平时存一个 weight 的 1/(TP × GTP_remat)，GEMM 前临时拼回 1/TP。手算一遍。h = 8192 的方阵 weight 用 bf16 存是 128 MiB。TP = 4 后每卡 32 MiB。再开 GTP_remat = 8，每卡平时只存 4 MiB，GEMM 前 all-gather 回 32 MiB。合起来是 1/32。

all-gather 和 weight gradient 怎么藏在计算后面

  1. Forward：第 i 层的 all-gather 和第 i − 1 层的 GEMM 同时跑，写成 \(\text{AG}(W_i) \parallel \text{GEMM}(W_{i-1})\)
  2. 链头：第一层前面没有 GEMM 可以盖，所以 L 层里藏住 L − 1 次 all-gather
  3. Cold start：第一次 forward 时每个 weight 的 all-gather 都是同步的，prefetch chain 从第二次 forward 才开始
  4. Backward：反着走，第 i − 1 层的 all-gather 和第 i 层的 dgrad 重叠
  5. Weight gradient：reduce-scatter 异步发出，finalize 推迟一步，所以第 i 层的 reduce-scatter 能和第 i − 1 层的 backward GEMM 重叠。链头后面没有 GEMM 了，所以用同步的 reduce-scatter

Overlap 的一般做法和 exposed communication 怎么算见 overlap。

必答点

  • GTP = TP × GTP_remat，每卡存每个 linear weight 的 1/(TP × GTP_remat)
  • GTP_remat 是 ZeRO-3 的做法：切开存，用前 all-gather，用完释放，gradient 走 reduce-scatter
  • 和 DP 轴上的 ZeRO-3 有两点区别：切在 model-parallel 轴，一次一个 weight
  • 第 i 层的 all-gather 和第 i − 1 层的 GEMM 重叠，L 层藏住 L − 1 次
  • Weight gradient 用 async reduce-scatter，finalize 推迟一步

追问

GTP_remat 里的各个 rank 算的是同一份数据吗？

不是。默认每个 GTP_remat rank 处理不同的 sample。开了 sequence sharding 后，各 rank 算同一个 microbatch 的不同 sequence 分段。

为什么不直接把 FSDP 的 bucket 缩到一个 weight？

FSDP 的 overlap 本来就是按 bucket 设计的，bucket 是为了不在很小的 parameter 上反复付 NCCL launch latency。GTP_remat 干脆不切小 tensor，LayerNorm、bias、MoE router 这些一直存完整的。

all-gather 出了 NVLink domain 还藏得住吗？

只靠一个 GEMM 藏不住。一个 GEMM 的时间够盖住 domain 内的 all-gather，不够盖跨 domain 的。MoE 的 routed-expert weight 属于后一种，所以单独用一条 one-block-ahead chain。

怎么打开，能和什么一起用？

--tensor-parallel-num-weight-shards 传的是 TP × GTP_remat 的总份数，必须是 TP 的整数倍。上面的例子 TP = 4、GTP_remat = 8，就传 32。它等于 TP 时 GTP_remat = 1，GTP 不生效。它能和 TP、SP、EP、DDP、CUDA Graph 叠加使用。
