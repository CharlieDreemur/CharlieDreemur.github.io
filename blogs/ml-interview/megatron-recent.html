Megatron Core 最近三个月发布了什么？
五条主线各接到哪道基础题？

英文问法What has the Megatron Core team shipped in the last few months? · Which recent Megatron Core feature interests you most, and why? · What do you know about our latest release?

考过推断，非面经。没有任何面经问过这道题，上面三个问法也是推断 · 依据是团队自己的 core 0.19.0 和 0.20.0 release notes、GTP 文档、determinism tracker #5785、Q4 roadmap #9232 · 面试前先读这一页，再按需要点进五个细节页

先弄清楚：每个概念是什么

Megatron Core、Megatron-Bridge、NeMo-RL
三个仓库。Megatron Core 是训练库本身。Megatron-Bridge 放各模型在各硬件上的 recipe。NeMo-RL 是 RL post-training 框架，0.8.0 的容器里装的就是 Megatron-Core 0.20.0 和 Megatron-Bridge 0.7.0。
Experimental
release notes 和文档里的标注。GTP 文档的原话是 API、配置和行为 "may change in future versions without notice"。
NVLink domain
一组互相用 NVLink 直连的 GPU，domain 内的通信比跨 domain 快得多。MFSDP v2、GTP、MegaMoE 的材料里都提到它。
All-to-all
EP 里把 token 发到 expert 所在的卡、算完再收回来的通信（见 MoE 与 Expert Parallel）。
Full-iteration CUDA Graph
把一整个 training iteration 的 kernel 录成一张 graph 再 replay，省掉逐个 launch 的开销（见 CUDA Graph）。

30 秒回答

I read the core 0.19 and 0.20 release notes, and I'd group the work into five threads. Megatron-FSDP v2 adds ZeRO-style sharding that can differ inside and across NVLink domains. Generalized Tensor Parallelism adds ZeRO-3-style weight sharding on the model-parallel axis. For MoE, expert-parallel communication gets faster with the NCCL EP backend and ShortcutMoE overlap, plus fused MegaMoE kernels on main. Bitwise-deterministic training is a multi-release effort with an overhead target under ten percent. And there's MXFP8 and NVFP4 training with full-iteration CUDA Graphs. Most of this is marked experimental, so I'd quote any limit together with the version I read.

面试里怎么用

  • 五条各说一句，再挑两条讲透
  • 引用时带版本，例如 "I read the core 0.20.0 release notes"
  • Experimental 的限制不要说成定论。0.20.0 写 MFSDP v2 的 optimizer checkpoint 不含 EP layout，main 上已经修掉了（PR #8230）
  • 不要说 HybridEP 已被弃用。Megatron-Bridge 0.7.0 的原话是 "HybridEP deprecation and full migration are deferred."，NeMo-RL 0.8.0 的 MoE recipe 还在用 HybridEP

题库里还没有的主题

  • Muon：0.20.0 加了 layer-sharded 的 distributed Muon（PR #6683）
  • Sequence packing 和 dynamic CP：0.20.0 加了 DP-balanced sequence packing。Dynamic CP 在 main 上改用标准的 train 和 eval schedule，旧名字是 hybrid CP（PR #7047）
  • RL 的 weight refit：NeMo-RL 0.8.0 的 NCCL reshard refit 把 DeepSeek-V3 671B 在 H100 上的 refit 从 14.9 s 降到 2.6 s（release notes）

这三个主题只列在这里，没有展开，也没有速查页。

追问

接下来一个季度团队要做什么？

Q4 roadmap #9232 的目标版本是 26.12，写着 "scope may change"。和这五条有关的有 "Tune MFSDP v2 for Nemotron and DeepSeek workloads" 和 "Benchmark NCCL EP recipes against DeepEP v2, including on AWS."，determinism 要扩到更多 kernel。

五条里挑哪两条讲透？

没有证据说哪条被问的概率高。按自己能接上的基础题挑，比如熟 ZeRO 和 TP 就讲 MFSDP v2 和 GTP。

NCCL EP、DeepEP v2、HybridEP 是什么关系？

三个都是 EP 的 token dispatcher backend，现在并存。0.20.0 里 DeepEP v2 是 experimental，Bridge 的 GB300 recipe 默认用 NCCL EP。细节见 EP communication。

GPTModel 还能用吗？

0.19.0 的 release notes 有一条 "GPTModel: deprecation announcement"，并把 HybridModel 叫作 "next-gen model class"。0.20.0 里 DeepSeek V4 由 HybridModel 支持。

为什么 MoE 做不了 full-iteration CUDA Graph？

PR #7075 的说法是 MoE 的 "data-dependent expert-dispatch buffers are not capture-safe"。NCCL EP 的对策见 low precision 和 CUDA Graph。
