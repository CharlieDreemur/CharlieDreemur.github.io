先弄清楚：每个概念是什么

Megatron Core、Megatron-Bridge、NeMo-RL
Megatron Core 是训练库。Megatron-Bridge 放各模型在各硬件上的 recipe。NeMo-RL 是 RL post-training 框架，容器里装着 Megatron Core 和 Megatron-Bridge。
Experimental
release notes 和文档里的标注，表示 API、配置和行为以后可能直接改掉，不另行通知。
NVLink domain
一组互相用 NVLink 直连的 GPU，domain 内的通信比跨 domain 快得多。
All-to-all
EP 里把 token 发到 expert 所在的卡、算完再收回来的通信（见 MoE 与 Expert Parallel）。

30 秒回答

Reading the team's recent release notes, I'd group the work into five threads. Megatron-FSDP v2 is Megatron's own fully sharded data parallel, and it can use different ZeRO levels inside and across NVLink domains. Generalized Tensor Parallelism shards each weight ZeRO-3 style along the model-parallel axis and prefetches the all-gather behind compute. For MoE, the work speeds up expert-parallel all-to-all: a new NCCL EP backend, ShortcutMoE overlap, and fused MegaMoE kernels. Bitwise determinism aims for bit-exact training on a fixed setup at low overhead. And there's MXFP8 and NVFP4 training with full-iteration CUDA Graphs. Most of this is experimental, so the limits change quickly.

五条主线

主线是什么，为什么做先会的基础题细节页
MFSDP v2Megatron 自己的 FSDP，能切到 ZeRO-1/2/3。NVLink domain 内外可以用不同级别，推断是为了让每层的 parameter all-gather 只走 NVLink。目前要求 TP = 1ZeROMFSDP v2
GTPGTP = TP × GTP_remat。GTP_remat 把 weight 再切开存，GEMM 前 all-gather 拼回来，省的是 weight 占的 GPU memory。文档说它是切在 model-parallel 轴上的 ZeRO-3TP、overlapGTP
MoE 的 EP communication三项工作都是为了减少 all-to-all 的开销。NCCL EP 是新的 dispatcher backend。ShortcutMoE 让 all-to-all 和 attention 重叠。MegaMoE 把 dispatch、expert 计算、combine 融成一个 kernelEPEP communication
Bitwise determinism目标是固定环境下两次训练每一位都相同，同时 overhead 要低。这样 loss spike 能原样重现，一次只换一个组件来 debugall-reducedeterminism
Low precision 和 CUDA GraphMXFP8 和 NVFP4 training 用更低的精度算 GEMM，选定的 tensor 留 FP32。Full-iteration CUDA Graph 把整步 capture 下来，省掉 kernel launch 开销。MFSDP v2 的 dense 配置支持它mixed precision、CUDA Graphlow precision

按实际的开发量看，这五条并不全。五条主线取自 release notes。代码里最活跃的还有四个方向，分别是 inference 和 RL 的训推 bitwise parity，HybridModel 取代 GPTModel，training config 从 argparse 迁到 typed config，全局 parallel_state 弃用。这四件事各是什么，见代码精读报告的第二节。

题库里还没有的主题

  • Muon：新加了 layer-sharded 的 distributed Muon
  • Sequence packing 和 dynamic CP：DP-balanced sequence packing，以及 dynamic CP，后者的旧名字是 hybrid CP
  • RL 的 weight refit：每步训练完要把新 weight 传给 inference 那一侧。NeMo-RL 新加的 NCCL reshard refit 让这一步快了很多

必答点

  • 五条主线和各自的基础题：MFSDP v2（ZeRO）、GTP（TP）、MoE 的 EP communication（all-to-all）、bitwise determinism（reduction order）、low precision 和 CUDA Graph（mixed precision）
  • 多数功能还是 experimental，限制变得很快，不要把某条限制说成定论
  • HybridEP 没有被弃用，彻底迁到 NCCL EP 的计划推迟了（见 EP communication）

追问

接下来一个季度团队要做什么？

roadmap 上和这五条有关的有三件事。MFSDP v2 针对 Nemotron 和 DeepSeek 的 workload 调优，NCCL EP 的 recipe 和 DeepEP 对比，determinism 扩到更多 kernel。roadmap 自己也写着范围会变。

五条里挑哪两条讲透？

没有证据说哪条被问的概率高。五条各说一句，再按自己能接上的基础题挑两条，比如熟 ZeRO 和 TP 就讲 MFSDP v2 和 GTP。

GPTModel 还能用吗？

还能用，但已经宣布要弃用。HybridModel 被叫作下一代 model class，DeepSeek V4 就是由它支持的。
