Vocab parallelism：embedding 和 LM head 怎么切？
cross-entropy 怎么算才不用 gather logits？

英文问法How do you shard a huge embedding table and the LM head? · Why split along the vocabulary, and where does communication happen? · How do you compute cross-entropy without gathering the full logits?

考过Microsoft MAI infra onsite 2026（整轮围绕大 embedding 和 LM head 的 distributed 切分，一直追问"为什么这么切、通信在哪里发生"，Pass，1p3a 1189843）· 快手（"这个列划分并行是什么？这里没用到all-gather啊？"）

先弄清楚：每个概念是什么

Embedding table
一张 [\(V\), \(h\)] 的表，lookup 就是按 token id 取一行。例：token 5 → 取第 5 行，一个 \(h\) 维向量。
Vocab-parallel embedding
表按行（vocab）切，每卡管一段连续的 id。像 \(t\) 个图书管理员各管一段书号：借书单发给所有人，只有管那段的人递出书，其他人递空手，合起来正好一本。例：\(V = 8\)、\(t = 2\)，token 5 → rank 0 输出 0，rank 1 输出 \(E[5]\)，all-reduce 求和 = \(E[5]\)。
LM head
[\(h\), \(V\)] 的矩阵，把 hidden 投成 \(V\) 个 logits。按 vocab 切就是 column parallel，每卡算 [\(b, s, V/t\)] 的 logits。和 embedding 共享 weight（weight tying）时用同一种切法。
Vocab-parallel cross-entropy
loss 只需要每个 token 的三个标量：logits 的 max、\(\sum e^{z}\)、目标 logit。每卡在自己的 \(V/t\) 列上算局部值，再 all-reduce 这三个标量，不用把 \(V\) 个 logits 拼回来。

看图：embedding 怎么查，cross-entropy 怎么算

30 秒回答

Megatron splits both along the vocabulary. The embedding is split by rows: each rank owns a range of token ids, looks up those it owns, outputs zeros for the rest, and an all-reduce sums the results, since exactly one rank contributes each token. The LM head is column-parallel over the same split, so each rank gets logits for its V/t slice. Instead of all-gathering b·s·V logits, cross-entropy runs in place: all-reduce MAX of the local max, all-reduce SUM of the local sum of exps, and all-reduce SUM of the target logit, which only one rank has. That's three b·s tensors instead of b·s·V, and logits memory drops by t.

推导 / 关键公式

Embedding

非本卡的 id 先映射到 0 号行去查，查完把输出置 0，再 all-reduce（开 SP 时换成 reduce-scatter）。

Cross-entropy：减 max 的 log-sum-exp 拆到各卡

\[ \ell = \log\sum_j e^{z_j - m} - (z_y - m) \] \[ m = \max_r m_r \quad \text{all-reduce MAX} \] \[ \textstyle\sum_j e^{z_j - m} = \sum_r S_r \quad \text{all-reduce SUM} \] \[ z_y = \sum_r z_y^{(r)} \quad \text{all-reduce SUM，非本卡填 0} \]

backward 全在本地：\(\partial\ell/\partial z_j = \mathrm{softmax}_j - \mathbb{1}[j = y]\)，只有拥有 \(y\) 的那张卡减 1。LM head 的 dX 再按 column parallel 的规矩 all-reduce。

代码（NumPy 模拟 t = 4）

rng = np.random.default_rng(0)
n, V, t = 6, 16, 4                    # n = b·s 个 token
z = rng.standard_normal((n, V)) * 5   # logits
y = rng.integers(0, V, n)             # target id
i = np.arange(n)
zs = z - z.max(1, keepdims=True)      # 单卡 reference
ref = np.log(np.exp(zs).sum(1)) - zs[i, y]

shards = np.split(z, t, axis=1)       # rank r 管 V/t 个词
m = np.max([zr.max(1) for zr in shards], 0)     # all-reduce MAX
S = sum(np.exp(zr - m[:, None]).sum(1)          # all-reduce SUM
        for zr in shards)
zy = 0
for r, zr in enumerate(shards):
    lo = r * V // t
    own = (y >= lo) & (y < lo + V // t)       # target 在本卡吗
    loc = np.where(own, y - lo, 0)            # 不在：index 置 0
    zy = zy + np.where(own, zr[i, loc], 0)    # all-reduce SUM
print(np.allclose(np.log(S) - (zy - m), ref))  # True

手算例子：省多少

\(b = 1\)、\(s = 4096\)、\(h = 8192\)、\(V = 131072\)（128K）、\(t = 8\)：

每卡不切按 vocab 切
embedding weight + Adam state（16 B/param，见 optimizer）16 GiB2 GiB
fp32 logits [\(b, s, V\)]2 GiB0.25 GiB

通信：gather logits 要搬 \(bsV\) ≈ 5.4 亿个元素；vocab-parallel CE 只 all-reduce \(3 \times bs\) 个 fp32，48 KiB。

必答点

  • Embedding 按 vocab（行）切：非本卡 token 输出 0 → all-reduce
  • LM head 按 vocab 切 = column parallel，每卡 \(V/t\) 的 logits；weight tying 时同一种切法
  • CE 不 gather logits：all-reduce MAX、SUM(exp)、SUM(目标 logit)，通信 \(bs\) 而不是 \(bsV\)
  • CE 的 backward 本地算 softmax − one-hot，不通信

追问

为什么不按 hidden 切？

Embedding 按 hidden 切，每卡只拿到部分维度，后面的层要完整 \(h\)，得 all-gather；LM head 按 hidden 切就是 row parallel，每卡是 [\(b, s, V\)] 的部分和，要 all-reduce \(bsV\) 个元素，太大。

还有别的切法吗？

按 token id 把查询路由到拥有那段的卡，查完再 all-to-all 发回。只搬真正用到的行，但高频 token 集中的卡会 load imbalance。

推理时不 gather logits 怎么 sampling？

每卡在自己的 \(V/t\) 里取 top-k，把 \(t \cdot k\) 个候选 gather 到一起再选全局 top-k。greedy 就是 \(k = 1\)。

weight tying 碰上 pipeline parallel 怎么办？

embedding 在第一个 stage、LM head 在最后一个 stage，各存一份。初始化时 all-reduce 让两份相同，每步再 all-reduce 两份的 gradient。

为什么 vocab 要 padding？

让每卡的 \(V/t\) 是 128 的倍数，logits GEMM 更高效。Megatron-LM 把 GPT-2 的 50257 补到 51200（\(128 \times 8\) 的倍数），多出来的 id 不会出现在数据里。
