给定模型和 cluster，怎么选 parallelism 配置？
（含 trillion-parameter training system design）

英文问法Given a model and a cluster, how do you choose TP, PP and DP sizes? · Design a distributed training system for a trillion-parameter language model.

考过NVIDIA Senior SWE, LLM Applications 2025-09 等（trillion-parameter system design，Aced 用户提交，NVIDIA 问过 3 次）· NVIDIA High Performance LLM Training Engineer（Glassdoor RVW105730158）· NVIDIA DL Engineer 慕尼黑 2026（"how distributed training works"，Glassdoor RVW104512401）· NVIDIA DL Engineer HM 轮（"parallel training methods"，Glassdoor RVW98332074）· Meta（"Design a Scalable MoE Pretraining Pipeline"）

先弄清楚：每个概念是什么

3D parallelism：卡数 \(= t\cdot p\cdot N\)
先把一份模型切成 \(t\times p\) 块放下（TP 切每层的矩阵，PP 按层分段），再把这一整套复制 \(N\) 份，各吃不同的数据（DP）。像一本书太厚，拆成 \(t\times p\) 个分册交给一组人，再组织 \(N\) 组人同时读。例：t = 8、p = 8，一份模型占 64 卡；1024 卡 → N = 16。
Communication 有轻有重
TP 每层 forward、backward 各 2 次 all-reduce，挡在计算前面。PP 只在 stage 边界传 activation（point-to-point）。DP 每个 step 才同步一次 gradient。像同桌随时讨论、隔壁传纸条、每周开一次全员会。
NVLink domain
一台机器的 8 张卡由 NVLink/NVSwitch 互连，带宽最高；跨机走 InfiniBand，慢得多。所以越重的 communication 放得越靠里。
Pipeline bubble
流水线开头要灌满、结尾要排空，这段时间卡在空转，占比 \((p-1)/m\)，\(m\) 是 micro-batch 数。interleaved 1F1B 再除以每卡的 chunk 数。例：p = 8、m = 96 → 7/96 ≈ 7.3%。
Memory 预算
model states 16 bytes/param，每卡分到 \(16\Psi/(t\cdot p)\)，再加 activation（见 training memory）。它决定一份模型至少切几份。

30 秒回答

I start with a memory budget, then place each kind of parallelism by how much it communicates. Model states take about 16 bytes per parameter plus activations, which tells me how many GPUs one replica needs. Tensor parallelism all-reduces inside every layer, so I keep it within a node on NVLink, usually 8. If the model still doesn't fit, I add pipeline parallelism across nodes, with many more micro-batches than stages to keep the bubble small. Context parallelism handles long sequences and expert parallelism handles MoE. All remaining GPUs go to data parallelism with a sharded optimizer. Then I tune micro-batch size and recomputation and check MFU.

怎么选：先算账，再按 communication 从重到轻往外套

一句话：TP 放机内（≤ 8），还放不下就跨机加 PP，CP / EP 按需加，剩下的卡全给 DP。

  1. 算账：\(16\Psi\) + activation，除以单卡显存 → 一份模型至少几张卡。
  2. TP 机内：\(t\) ≤ 每台 GPU 数（通常 8）；再大 GEMM 变小、通信变多（TP communication）。
  3. PP 跨机：取放得下的最小 \(p\)，保证 \(m \gg p\)，用 interleaved 1F1B（PP）。
  4. 按需：sequence 很长加 CP；MoE 加 EP。
  5. 剩下给 DP：\(N = \text{卡数}/(t\cdot p)\)，配 distributed optimizer / ZeRO（DP、ZeRO、FSDP）。
  6. 调优：micro-batch size、recompute、overlap，看 MFU。

手算例子：175B GPT，1024 张 A100-80GB

\(h = 12288\)、\(L = 96\)、\(s = 2048\)，global batch 1536 条，每台 8 卡。

  1. model states \(16 \times 175\text{B} = 2.8\) TB → 一份模型至少 35 卡。
  2. \(t = 8\)，占满一台机器。
  3. \(p = 4\)：每卡 \(2.8\text{ TB}/32 = 87.5\) GB，放不下。\(p = 8\)：43.75 GB，加 activation（SP + selective recompute、\(b = 1\)，第一个 stage 存满 \(L\) 层：\(34sbhL/t \approx 10.3\) GB）共约 54 GB ✓
  4. \(N = 1024/64 = 16\)；每个 pipeline 分到 96 条 → \(m = 96\)，bubble 约 7.3%（\(7/96\)）

Trillion-parameter system design 还要讲

  • 算时长：\(6\Psi D\) ÷（卡数 × 峰值 × MFU），见 FLOPs 与 MFU；Megatron 估 1T 模型、450B token、3072 卡约 84 天。
  • 容错：Llama 3 405B 54 天里中断 466 次 → 定期存 distributed checkpoint（异步写、能换并行度重新切分），自动发现坏卡并重启。
  • 数据与监控：data pipeline 不能让 GPU 等；盯 MFU、loss spike、慢卡。

必答点

  • 先算 memory（\(16\Psi\) + activation），决定 \(t\cdot p\)
  • TP 机内 ≤ 8；PP 跨机，\(m \gg p\)；剩下全给 DP + ZeRO/FSDP
  • CP 管长 sequence，EP 管 MoE
  • 例：175B、1024 卡 → \(t = 8\)、\(p = 8\)、\(N = 16\)
  • 1T 规模还要 checkpoint、自动重启、监控

追问

为什么 TP 不跨机？

TP 每个 micro-batch 的每一层都要 all-reduce，而且挡在计算前面；PP 只有便宜的 point-to-point。Megatron 实测 TP 和 PP 组合没选好，吞吐可以差 2 倍，所以 TP 用到单机 GPU 数为止，再大的模型靠 PP 跨机。

用了 distributed optimizer（ZeRO-1）之后呢？

12 bytes 的 optimizer state 再按 \(N\) 切。上例 \(p = 8\) 时每卡 model states 从 43.75 GB 降到约 13 GB，\(p\) 可以降到 2–4，stage 少、bubble 小。ZeRO-1/2 的 communication 量和普通 DP 一样。

micro-batch size 怎么选？

\(b\) 大，GEMM 效率高；但 \(m = B/(N\cdot b)\) 变小，bubble 变大，activation 也变多。没有通用答案，要实测，Megatron 的 1B 模型例子里最优是 \(b = 4\)。

DP 能一直加吗？

受 global batch 限制。Llama 3 从 8K 卡扩到 16K 卡时 global batch 固定为 16M token，每个 DP group 的 batch 减半，MFU 从 43% 降到 41%。
