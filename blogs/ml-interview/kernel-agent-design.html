怎么设计一个自动优化 CUDA kernel 的 agent？

先弄清楚：每个概念是什么

题目
给一个 PyTorch op，让 agent 写出又对又快的 CUDA 或 Triton kernel。例：把 conv + bias + ReLU 写成一个 kernel。
One-shot
LLM 只生成一次，不看任何执行结果。
Harness
agent 外面那层确定性的代码。它先编译，再查正确性，最后计时，并决定一个候选留不留（见 LLM harness）。
Profiler feedback
Nsight Compute 给的硬件指标。它告诉 agent 瓶颈是 memory bound 还是 compute bound，只给 runtime 的话 agent 不知道该改哪里。
fast_p
KernelBench 的指标，指既正确、又比 PyTorch 快 p 倍以上的题目比例。fast_1 就是比 PyTorch 快的比例。

30 秒回答

I'd start with one-shot generation, which rarely beats PyTorch. So I'd add a loop that feeds compiler errors and correctness diffs back, then timing and profiler metrics so the agent knows what the bottleneck is. A single chain gets stuck, so I'd keep a population of candidates with beam or evolutionary search. Stronger search finds holes in the harness, so the harness has to be hardened. Finally, I'd use the same environment to train the model with RL, so the skill is in the model instead of in expensive search. In production I'd keep search simple and put the effort into verification, as FlashVector does.

FlashVector 的搜索很简单

按这条 version chain 看，FlashVector 有 v3 的 profile 循环和 v5 那种 agent 改不了的 harness，没有 v4 的搜索。它是单链循环，每轮随机抽一层，一轮只做一个改动。Diagnose 给假设排序，用的是时间占比乘预期收益。

同类系统里，Meta 的 KernelEvolve 用 MCTS 加 evolution，AlphaEvolve 用 evolution，Baseten 和 FlashVector 一样是带排序的贪心循环。四家都报告了生产落地，所以搜索的复杂度和进没进生产没有正相关。FlashVector 把精力放在 verify 和交付上。面试里讲完 version chain 可以补一句，上生产先把 harness 做牢，搜索够用就行。

必答点

  • 从 one-shot 讲起，每一版只解决上一版的一个问题
  • 反馈有两层：先过编译和正确性，再给 runtime 和 profiler 指标
  • agent 只提案，去留由它改不了的 harness 判定
  • 搜索越强越会钻漏洞，所以 v4 和 v5 要连着讲
  • RL 把能力训进模型，省掉每个 kernel 都搜一遍的 token
  • FlashVector 用单链循环进了生产，精力在 verify 和交付

追问

FlashVector 每轮随机抽一层，为什么不先做瓶颈最大的那层？

论文没有解释，也没有按各层的时间占比加权。这一条适合当反问。自己设计时可以按时间占比加权抽样，这是我的想法，不是论文的做法。

循环什么时候停？

有三种停法。结果接近硬件的物理上限（speed of light），连续几轮没有提升，或者预算用完。FlashVector 的 Algorithm 1 只写了到迭代上限或优化目标达成，具体数值论文没写。

没有 profiler feedback 会怎样？

LLM 会一直沿着第一版的写法改。Meta KernelAgent 的 matvec 例子里，不给硬件反馈的版本比 torch.compile 还慢，数字见 search 方法怎么选。

让 agent 写 CUDA 还是 Triton？

DSL 更容易写对。μCUTLASS 论文在 59 道 KernelBench 题上用 GPT-5-mini，直接写底层代码的 geomean 是 0.40x，改写 DSL 后是 1.27x。

循环的控制流放在 LLM 里还是代码里？

放在确定性的代码里。worker 的生命周期、预算和 early exit 由 Python orchestrator 管，LLM 只提案和写代码，这是 Meta KernelFalcon 的做法。
