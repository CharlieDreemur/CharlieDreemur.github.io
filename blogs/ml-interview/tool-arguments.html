Tool calling 最容易错在哪？
为什么 argument 是瓶颈，怎么改？

英文问法Where do tool-calling agents fail most? · How do you measure and improve argument accuracy?

考过推断，非面经。依据：Apple 的 ASTRA-bench 结论 "Argument generation emerging as the primary bottleneck"（arXiv 2603.01357）· Apple JD 写 "quality, reasoning, and tool-use accuracy of agentic systems"（200656115）

先弄清楚：每个概念是什么

Tool selection 与 argument generation
选哪个 tool，和参数怎么填，是两件事。例：选对了 search_messages，但 sender 填的是“我妈”而不是 contact ID。
Personal context
参数的值常常在用户的数据里，这句话里找不到。“我妈”“上次那家店”都要先查出来，才能填进参数。
Schema validation
执行前检查参数的类型、必填项、取值范围。
Constrained decoding
解码时只允许生成符合 JSON schema 的 token。它保证格式合法，不保证值正确。
Argument accuracy
逐个参数和 gold 比较。例：3 个参数对了 2 个 → 0.67；整个调用全对才算对的口径下是 0。

30 秒回答

Tool calls fail in two ways: picking the wrong tool, or filling in the wrong arguments. Apple's ASTRA-bench found that argument generation was the main bottleneck when agents work over personal context. That makes sense, because the right value often isn't in the request: "my mom" or "last Friday" has to be resolved from the user's data first. I'd measure selection and arguments separately. To improve: resolve entities and dates with dedicated tools before the main call, validate arguments against the schema, return precise errors so the model can retry, and add examples for the confusing fields.

错误类型和对策

错误例子对策
格式错缺必填项、类型不对schema validation、constrained decoding
值没 resolvesender="我妈"先调 contact resolver，拿到 ID 再填
时间错“上周五”算错日期把当前日期放进 context；日期计算用代码

依赖没处理第二步的参数要用第一步的结果按依赖顺序执行，返回结果带稳定的 ID

必答点

  • selection 和 argument 分开量，argument 再按参数拆开
  • ASTRA-bench：personal context 下 argument 是主要瓶颈
  • 原因：值藏在用户数据里，要先 resolve
  • 对策：先 resolve、再校验、错误信息要具体、可重试
  • constrained decoding 只管格式

追问

constrained decoding 能解决 argument 错误吗？

只能解决格式错。日期填错、人填错在格式上都是合法的。值的正确性要靠 resolve 和校验。

argument accuracy 怎么算才公平？

先做归一化：日期格式统一、ID 统一，等价的写法不能算错。然后分开报三个数：tool selection accuracy、逐参数 accuracy、整个调用全对的比例。

tool 的描述怎么写，模型才不容易填错？

参数名自解释。写明单位、时区和格式。能枚举的给枚举值。给一两个调用例子。容易混的两个参数写清区别。

填错了怎么恢复？

返回结构化的错误：哪个参数、为什么不对、合法值是什么。模型据此重试，重试次数设上限，到上限就告诉用户。
