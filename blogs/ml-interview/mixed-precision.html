Mixed precision 怎么做？
FP16、BF16、FP8 有什么区别？

英文问法Why do we train LLMs in BF16 rather than FP16? · What is loss scaling and why is it needed? · Why keep FP32 master weights? · E4M3 vs E5M2?

考过面经：国内：讯飞（"为什么大模型训练用BF16？"）· 网易（"FP8格式差异（E4M3高精度窄范围 vs E5M2宽动态范围）"）· 牛客（"是否了解混合精度，FP16 和 BF16 的区别？"）· 智谱（"nvfp4的原理是什么样的，怎么做缩放的，在哪个维度缩放？"）

先弄清楚：每个概念是什么

Exponent 与 mantissa（range vs precision）
浮点数 = 符号 × 1.mantissa × 2exponent。exponent 的 bit 决定尺子有多长（能表示多大、多小，range），mantissa 的 bit 决定刻度有多密（precision）。例：1 附近相邻两个数的间距，FP16 是 \(2^{-10}\approx 0.001\)，BF16 是 \(2^{-7}\approx 0.008\)。
Underflow / overflow
比最小值还小就变成 0，比最大值还大就变成 inf。FP16 只有 5 位 exponent，两头都容易出事。例：np.float16(1e-8) = 0；np.float16(70000) = inf（FP16 最大 65504）。
Loss scaling
backward 之前把 loss 乘 \(S\)，chain rule 让所有 gradient 一起放大 \(S\) 倍，小 gradient 就不会变成 0。optimizer 更新前再除回去。像录音前先把太小的声音放大。例：gradient \(10^{-8}\) 存成 FP16 是 0；乘 \(S = 2^{16}\) 得 \(6.55\times10^{-4}\)，存得下；在 FP32 里除回来仍 ≈ \(10^{-8}\)。
FP32 master weights
weight 的"正本"用 FP32 保存和更新，forward/backward 用它转出来的 16-bit 副本。因为 update 比 weight 小太多时，16-bit 加法会把它整个舍掉。例：\(w = 1\)、update \(= 10^{-4}\)：FP16、BF16 算出来都还是 1；FP16 连加 10000 次仍是 1，FP32 是 2.0002。
Per-tensor scaling（FP8）
FP8 的 range 太窄，一个全局 loss scale 照顾不了所有 tensor，于是每个 tensor 各配一个 scale，把它的 amax（最大绝对值）对准格式的最大值。Transformer Engine 的 delayed scaling 用前几个 iteration 的 amax history 来算这个 scale。

30 秒回答

Mixed precision runs matmuls in 16-bit or FP8 and keeps the sensitive parts in FP32: master weights for the update, accumulation inside matmuls, and reductions like softmax and norms. FP16 has only 5 exponent bits, so small gradients underflow; dynamic loss scaling fixes that: multiply the loss by S, unscale before the step, and on inf or NaN skip the step and halve S. BF16 keeps FP32's 8 exponent bits, so it has FP32's range and needs no loss scaling, but with 7 mantissa bits we still need FP32 master weights. FP8 uses E4M3 for weights and activations and E5M2 for gradients, with a scale per tensor.

loss scaling：backward 是线性的，放大 loss 就放大所有 gradient

\[ \nabla_\theta (S\cdot L) = S\cdot \nabla_\theta L \]

dynamic loss scaling（PyTorch GradScaler 默认值）：

\[ S_0 = 2^{16};\quad \text{有 inf/NaN} \Rightarrow \text{跳过这步},\ S \leftarrow S/2 \] \[ \text{连续 2000 步正常} \Rightarrow S \leftarrow 2S \]

master weight：FP16 有 10 位 mantissa，weight 比 update 大超过 2048 倍时，\(w + \Delta w\) 舍入后还是 \(w\)，这次 update 就丢了。

一个 training step

  1. FP32 master weight → 转出 BF16/FP16 副本
  2. forward：matmul 16-bit 输入、FP32 accumulate；softmax、norm 统计量用 FP32
  3. loss × \(S\) → backward，得到 16-bit gradient（BF16 时 \(S = 1\)）
  4. gradient ÷ \(S\)，检查 inf/NaN，再 clipping → 更新 FP32 master weight

显存：每个 parameter 16 bytes（2 + 2 + 4 + 4 + 4），见 optimizer 和 training memory。

必答点

  • 三件套：FP32 master weight + loss scaling + FP32 accumulation；matmul 低精度，reduction 和 update 用 FP32
  • FP16：5 位 exponent，range 窄 → gradient underflow → 要 loss scaling
  • BF16：8 位 exponent，range 同 FP32，不用 loss scaling；只有 7 位 mantissa，仍要 FP32 master weight
  • dynamic loss scaling：溢出就跳过这步、\(S\) 减半；长时间不溢出再翻倍
  • FP8：E4M3（±448）用于 forward，E5M2（±57344）用于 gradient，每个 tensor 一个 scale

追问

为什么大模型都用 BF16，不用 FP16？

BF16 和 FP32 的 range 一样，不用调 loss scale，也不怕超过 65504。PyTorch 文档提醒，多数 BF16 预训练的模型放进 FP16 时 gradient 会 overflow。代价是 precision 低，靠 FP32 master weight 和 FP32 accumulate 补回来。

loss scale 选多大？太大会怎样？

只要不 overflow，越大越好。可以选 \(S\) 使 \(S\cdot\max|g| < 65504\)。太大会出 inf/NaN，所以实际用 dynamic：跳过这步、\(S\) 减半。\(S\) 取 2 的幂，乘除不引入误差。

FP8 为什么不能也用一个全局 loss scale？

FP8 的 range 够放下任意一个 tensor，但放不下所有 tensor，所以每个 tensor 一个 scale。溢出时直接 saturate 到最大值，不再跳过 step（FP8 溢出太频繁）。delayed scaling 用历史 amax，省掉现算 amax 多扫一遍数据。

MXFP8 / NVFP4 怎么缩放？在哪个维度？（智谱）

按 block 缩放：MXFP8 每 32 个连续元素一个 E8M0 scale（2 的幂）；NVFP4 每 16 个元素一个 E4M3 scale，再加一个 per-tensor FP32 scale。block 沿 matmul 的 reduction 维连续；NVFP4 的 weight 用 16×16 的 2D block，转置后值不变。NVFP4 训练还用 Random Hadamard Transform 打散 outlier，gradient 用 stochastic rounding。

哪些 op 必须留在 FP32？

大的 reduction 和容易溢出的 op（softmax、layer_norm、cross_entropy、exp/log、sum，PyTorch autocast 自动放 FP32）、matmul 的累加、optimizer update 和 Adam state。逐元素 op 受 memory bandwidth 限制，内部用 FP16 还是 FP32 算，速度一样。
