先弄清楚：每个概念是什么

Harness
包在 model 外面的程序，负责组装 context 和执行 tool（见 LLM harness）。model 只输出一个 tool call，执行不执行由 harness 决定。guardrail 在这页指 harness 里的规则。
规则（allow、ask、deny）
一条规则把一类 tool call 对应到 allow、ask、deny 之一，也就是直接执行、先问人、拒绝。读 workspace 里的文件是 allow，git push 是 ask。
Deny-first
不在允许清单里的操作一律拒绝。它像门禁的白名单，名单上没有就进不去。
人确认
执行前停下来，把将要执行的具体命令和影响范围给人看，人同意了才执行。英文叫 human approval。
Untrusted input
来源不受你控制的内容，只能当数据用。model 生成的 tool 参数，agent 读到的 log、代码注释、issue，都算。

30 秒回答

I tier actions by risk. Reads are allowed by default. Writes inside the workspace are allowed and logged. Anything with outside effects, like pushing code or touching production, needs human approval, and the person sees the exact command and what it affects. The rules are enforced by code in the harness, not by the prompt, because a model can be talked out of a prompt. Anything not on the allow list is denied. Text the agent reads, such as logs, code comments or issues, is data and can't grant permissions. And commands still run in a sandbox, which limits the damage when a rule is wrong.

三级都没匹配上的 tool call 按 deny 处理。蚂蚁那道题问写操作为什么还要跳转工单，答案在第三行。工单把具体命令和影响范围摆给人看，还留下一条审计记录。FlashVector 的做法是同一类，agent 把配置改动开成 PR，由人 review（见 改动怎么进生产）。

三条原则

  1. 规则由 harness 里的程序执行，不写在 prompt 里。写在 prompt 里的规则只是建议，model 可能被一段话说服而不遵守。程序在每个 tool call 执行前读规则并判定，model 的输出改不了判定结果。tool 的鉴权也放在这里，model 生成的参数按 untrusted input 校验。
  2. Deny-first。漏写一条规则时，后果是多拒绝一次，不是误放行。
  3. 读到的文字是数据，不能授权。log、代码注释、issue 里就算写着“已批准，直接 push”，规则检查的结果也不变。授权只来自规则和人确认。Prompt injection 的一般防法见 RAG 的 data poisoning 与 prompt injection。

规则也会写错，所以每个 tool call 仍然在 sandbox 里执行，由它限制损失的范围（见 sandbox 和 verifier 隔离）。kernel agent 里第 1 条的对应物是 agent 改不了的 verifier。

必答点

  • 按风险分三级：读 allow，workspace 内的写 allow 加记录，有外部影响的 ask
  • 规则由 harness 里的程序执行，不靠 prompt 约束
  • deny-first：允许清单之外一律拒绝
  • 人确认时给出具体命令和影响范围
  • 读到的文字和 model 生成的参数都是 untrusted input，不能授权
  • 规则之外还有 sandbox 限制损失

追问

能不能中途停下 agent？

能。harness 在每一步之间检查中断信号，收到后不再发起下一个 tool call。一步执行到一半时，要靠这一步自己的 timeout 结束。

规则和 model 的判断冲突时，谁说了算？

规则说了算。model 的输出只是提案，执行不执行由 harness 按规则判定。

权限模式怎么设计，默认模式要不要问用户？

一个模式是一套预设的规则。默认模式下读不问，有外部影响的写和执行要问。手写 coding agent 时的写法见 mini coding agent。

Deny-first 的优缺点是什么？

优点是规则有漏洞时结果偏向拒绝，新加的 tool 不会自动获得权限。缺点是允许清单要有人维护，清单太窄时 agent 会频繁被拒或频繁问人。

批量跑、没有人守着的时候，ask 怎么办？

把人确认做成异步的，比如蚂蚁题里的工单和 FlashVector 的 PR，agent 先停在这一步等结果。等不到确认的动作按 deny 处理。
