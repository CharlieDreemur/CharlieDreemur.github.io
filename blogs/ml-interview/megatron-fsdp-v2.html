Megatron-FSDP v2 是什么？
为什么 NVLink domain 内外可以用不同的 ZeRO 级别？

英文问法What is Megatron-FSDP v2, and which ZeRO levels can it shard to? · Why would you pick different sharding levels inside and across NVLink domains? · Why does it have its own optimizer instead of reusing the distributed optimizer?

考过推断，非面经。没有任何面经问过这道题 · 依据是团队自己的材料：core 0.20.0 release notes 的 Parallelism 一节、PR #5865 和 #6873 的描述、MFSDP design doc、roadmap #6812 · 这些功能在 0.20.0 标着 experimental，下面每条限制都写明是哪个版本的说法

先弄清楚：每个概念是什么

MFSDP v2
Megatron 自己的 fully sharded data parallel 的第二版。0.19.0 的 release notes 还写着 "MFSDP v2 is under development"，0.20.0 通过一个 experimental 的 Megatron Core adapter 接了进来。
ZeRO 级别
一共四级，配置里叫 sharding strategy，名字是 no_shard（DDP）、optim（ZeRO-1）、optim_grads（ZeRO-2）、optim_grads_params（ZeRO-3）。每级切什么、每卡多少显存见 DP、ZeRO、FSDP。
NVLink domain
一组互相用 NVLink 直连的 GPU，像同一间办公室里的人。例：DGX H100 一台 8 卡是一个 domain。GTP 文档把 GB200 NVL72 叫作 "a 72-GPU NVLink domain"。
Hybrid FSDP
把 DP 的 rank 排成两层。inner 轴 dp_shard 是 domain 里的 N 张卡，outer 轴 dp_outer 是 M 个 domain，每层各选一个 ZeRO 级别。
FullyShardedOptimizer
MFSDP v2 专用的 optimizer 类，管它自己切开的 parameter 和 gradient。DistributedOptimizer 留给 DDP 和 MFSDP v1。

看图：domain 内一个级别，domain 之间另一个级别

30 秒回答

MFSDP v2 is Megatron's own fully sharded data parallel. It supports no-shard and ZeRO-1, 2 and 3, and it can put data-parallel ranks on two axes, each with its own level. The 0.20.0 release notes say you can set different ZeRO levels inside and across NVLink domains. They don't say why. My reading is that ZeRO-3 gathers parameters for every layer, which is cheap on NVLink and expensive across nodes, so you shard fully inside a domain and keep cross-domain traffic to once per step. It uses its own FullyShardedOptimizer. In 0.20.0 the adapter is experimental and requires TP and expert TP of one.

两层各切到哪一级

Design doc 写明 MFSDP v2 不给 HSDP、HFSDP 写特例，每个 DP 轴各自指定 parameter、gradient、optimizer state 怎么放。下表是两个常见组合，N 是 inner 轴的大小，M 是 outer 轴的大小。

名字outer 轴inner 轴parameter 和 gradientoptimizer state
HSDPno_shardZeRO-3inner 上 sharded (N)；outer 上 parameter 是 replicated (M)，gradient 是 partial (M)sharded (N)，replicated (M)
HFSDPZeRO-1ZeRO-3同上sharded (N × M)

PR #6873 还写了 "ZeRO-2 and ZeRO-3 on the outer axis come for free"。

手算一遍。7B 模型的 model states 是 \(16\Psi\) = 112 GB，2 个 domain 各 8 张卡，所以 N = 8、M = 2。16 张卡全部 ZeRO-3 时每卡 7 GB，但每层的 parameter all-gather 要跨 domain。HSDP 每卡 \(16\Psi/8\) = 14 GB，all-gather 只在 domain 内。HFSDP 每卡 \(4\Psi/8 + 12\Psi/16\) = 3.5 + 5.25 = 8.75 GB。这是按 \(16\Psi\) 的口径估的，不是 Megatron 给的数字。

为什么按 NVLink domain 分层（推断）

0.20.0 的 release notes 只有一句 "The user can specify different ZeRO levels for inter-nvlink domains and intra-nvlink domains."，没有给理由。PR #6873 和 design doc 也没有给。下面是推断。

ZeRO-3 的每个 unit 在 forward 和 backward 前都要 all-gather 一次 parameter，这些通信要藏在计算后面才不拖慢训练。DGX H100 上 NVLink 单向约 450 GB/s，跨机每卡的网卡是 50 GB/s，差约 9 倍（数字见 TP communication）。所以 inner 轴放在 domain 里切到 ZeRO-3。outer 轴的 gradient reduction 每步只做一次，在最后一个 micro-batch 之后，HFSDP 另外在下一步开头把更新后的 parameter all-gather 回来。PyTorch FSDP 的 HYBRID_SHARD 和 HSDP 是同一个布局，PyTorch 文档给的理由是 "expensive all-gathers and reduce-scatters are only done within a node"。

必答点

  • MFSDP v2 是 Megatron 自己的 FSDP，0.20.0 里是 experimental 的 adapter
  • 四级：no_shard、ZeRO-1、ZeRO-2、ZeRO-3
  • Hybrid FSDP 有 inner 和 outer 两个轴，各选一级。HSDP 的 outer 是 no_shard，HFSDP 的 outer 是 ZeRO-1，inner 都是 ZeRO-3
  • 分层的理由是推断：每层的 parameter all-gather 留在 NVLink 上，跨 domain 每步只同步一次
  • Optimizer 是 FullyShardedOptimizer，DistributedOptimizer 留给 DDP 和 MFSDP v1
  • 0.20.0 的限制：TP=1、expert TP=1；optimizer checkpoint 不含 EP layout；full-iteration CUDA Graph 只限 dense

追问

为什么不复用 DistributedOptimizer？

PR #5865 的理由是 DistributedOptimizer "has strong assumptions about DDP API/classes such as DistributedDataParallel and ParamAndGradBuffer"。MFSDP v1 复用了它，但 PR 说这种复用是 "shallow"，大部分 DDP 的代码靠 if use_megatron_fsdp 分支绕过去。

dense 部分和 MoE 部分能用不同的配置吗？

能。release notes 写 "different configs for the dense section and the MoE section"。PR #7012 里 num_distributed_optimizer_instances 管 dense 的 mesh，expert_num_distributed_optimizer_instances 管 expert 的 mesh。

outer 轴存不存在、用哪一级，由什么决定？

PR #6873 写 num_distributed_optimizer_instances "decides only whether an outer axis exists"，outer_dp_sharding_strategy "decides what lives on it"。

TP=1 这个限制会一直在吗？

不能当定论。9 月 12 日合入的 PR #7220 还写着 "TP and PP remain unsupported"，9 月 23 日 PR #6486 就加上了 PP。Q4 roadmap 里 MFSDP 的几条是 "Tune MFSDP v2 for Nemotron and DeepSeek workloads" 和加 Muon、PP/VPP、combined 1F1B，读到的条目里没有 TP。

它和 GTP 都像 ZeRO-3，区别在哪？

MFSDP v2 沿 data-parallel 轴切。GTP_remat 沿 model-parallel 轴切，一次只 all-gather 一个 weight，可以和 TP 叠在一起，见 GTP。
