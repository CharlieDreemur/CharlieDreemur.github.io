Megatron-FSDP v2 是什么？
为什么 NVLink domain 内外可以用不同的 ZeRO 级别？

英文问法What is Megatron-FSDP v2, and which ZeRO levels can it shard to? · Why would you pick different sharding levels inside and across NVLink domains? · Why does it have its own optimizer instead of reusing the distributed optimizer?

考过推断，非面经，题目是按团队自己的 release notes、PR 描述和 design doc 推断的

先弄清楚：每个概念是什么

MFSDP v2
Megatron 自己的 FSDP 第二版，通过一个 adapter 接进 Megatron Core。
ZeRO 级别
配置里叫 sharding strategy，名字就写着切什么。no_shard 是 DDP，什么都不切。optim 是 ZeRO-1，切 optimizer state。optim_grads 是 ZeRO-2，再切 gradient。optim_grads_params 是 ZeRO-3，连 parameter 也切。细节见 DP、ZeRO、FSDP。
NVLink domain
一组互相用 NVLink 直连的 GPU。例：一个 GB200 NVL72 机柜就是一个 NVLink domain。
Hybrid FSDP
把 DP 的 rank 排成两层。inner 轴 dp_shard 是 domain 里的 N 张卡，outer 轴 dp_outer 是 M 个 domain，每层各选一个 ZeRO 级别。

看图：domain 内一个级别，domain 之间另一个级别

30 秒回答

MFSDP v2 is Megatron's own fully sharded data parallel. It supports no-shard and ZeRO-1, 2 and 3, and puts data-parallel ranks on two axes, each with its own level. The release notes say the levels can differ inside and across NVLink domains, without saying why. My reading: ZeRO-3 gathers parameters for every layer, which is cheap on NVLink but expensive across nodes, so you shard fully inside a domain and sync across domains once per step. It has its own FullyShardedOptimizer, because the distributed optimizer assumes DDP's classes. The adapter is still experimental and currently requires TP and expert TP of one.

两层各切到哪一级

HSDP、HFSDP 不是特例。每个 DP 轴各自指定 parameter、gradient、optimizer state 怎么放。

名字outer 轴inner 轴parameter 和 gradientoptimizer state
HSDPno_shardZeRO-3inner 上 sharded (N)。outer 上 parameter 是 replicated (M)，gradient 是 partial (M)sharded (N)，replicated (M)
HFSDPZeRO-1ZeRO-3同上sharded (N × M)

outer 轴换成 ZeRO-2 或 ZeRO-3 也支持，不用另写代码。

每卡的 model states 按 mixed precision 加 Adam 的 \(16\Psi\) 算，其中 \(4\Psi\) 是 parameter 和 gradient，\(12\Psi\) 是 optimizer state。N × M 张卡全部 ZeRO-3 时每卡 \(16\Psi/(NM)\)。HSDP 每卡 \(16\Psi/N\)。HFSDP 的 optimizer state 在两层都切，每卡 \(4\Psi/N + 12\Psi/(NM)\)。

手算一个例子。7B 模型 \(16\Psi\) = 112 GB，2 个 domain 各 8 张卡，N = 8、M = 2。16 张卡全部 ZeRO-3 时每卡 7 GB，但每层的 parameter all-gather 要跨 domain。HSDP 每卡 14 GB，all-gather 只在 domain 内。HFSDP 每卡 3.5 + 5.25 = 8.75 GB。

为什么按 NVLink domain 分层（推断）

release notes 只说 domain 内外可以用不同的 ZeRO 级别，没有给理由。下面是推断。

ZeRO-3 的每个 unit 在 forward 和 backward 前都要 all-gather 一次 parameter。NVLink 的带宽比跨机的网卡高得多（见 TP communication），所以 inner 轴放在 domain 里切到 ZeRO-3。outer 轴的 gradient reduction 每步只做一次，在最后一个 micro-batch 之后。HFSDP 还要在下一步开头把更新后的 parameter all-gather 回来。PyTorch FSDP 的 HYBRID_SHARD 和 HSDP 是同一个布局，文档给的理由是 "expensive all-gathers and reduce-scatters are only done within a node"。

必答点

  • MFSDP v2 是 Megatron 自己的 FSDP，支持 no_shard 和 ZeRO-1/2/3
  • Hybrid FSDP 有 inner 和 outer 两个轴，各选一级。HSDP 的 outer 是 no_shard，HFSDP 的 outer 是 ZeRO-1，inner 都是 ZeRO-3
  • 分层的理由是推断出来的，让每层的 parameter all-gather 留在 NVLink 上，跨 domain 每步只同步一次
  • Optimizer 是 FullyShardedOptimizer，因为 DistributedOptimizer 绑定了 DDP 的类，它留给 DDP 和 MFSDP v1
  • 目前的限制是 TP = 1、expert TP = 1，full-iteration CUDA Graph 只限 dense 配置

追问

为什么不复用 DistributedOptimizer？

DistributedOptimizer 对 DDP 的类有很强的假设，比如 DistributedDataParallel 和 ParamAndGradBuffer。MFSDP v1 对它的复用只是表面上的，大部分 DDP 代码靠 if use_megatron_fsdp 分支绕过去。v2 干脆自己写了 FullyShardedOptimizer。

dense 和 MoE 部分的 sharding 能分开配吗？

能。有没有 outer 轴、outer 轴切到哪一级，是两个独立的配置。dense 部分和 MoE 部分各配各的，expert 有自己的一套 mesh。

TP=1 这个限制会一直在吗？

不能当定论。PP 原来也写着不支持，没过多久就加上了。但 roadmap 里 MFSDP 的计划没有提 TP。
