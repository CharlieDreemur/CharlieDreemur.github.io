用 RL 训练写 kernel 的模型，
reward 怎么设计？

英文问法How would you design the reward for training a model to write fast kernels? · Why not use raw speedup as the reward? · How do you assign credit across refinement turns?

考过推断，非面经。没有 Unity 自己的材料，也没有面经原题 · 依据是三篇公开工作：Kevin-32B、CUDA Agent、CUDA-L1 · 研究向，和你做过的 RL environment 接得上，可以主动带出来

先弄清楚：每个概念是什么

Reward
模型每交一个 kernel，环境给的一个分数。训练就是让这个分数变高，所以 reward 奖什么，模型就学什么。
Speedup
reference 的运行时间除以生成的 kernel 的运行时间，大于 1 才是变快。
Multi-turn
一条 trajectory 里模型改好几轮，每一轮都交一个 kernel。Kevin 训练时每题 16 条 trajectory，每条 4 个 refinement step。
Credit assignment
最后的 kernel 快了，功劳怎么分给前面几轮。
Milestone reward
不看具体快多少倍，只看过了哪一档。

30 秒回答

Incorrect kernels get zero or a negative reward, and correct ones earn more for speedup. Kevin uses 0.3 plus the speedup, and each refinement step also gets the discounted sum of later scores with gamma 0.4, so early steps get credit for later gains. CUDA Agent found raw speedup has outliers and favors easy kernels, so it uses discrete milestones: minus one for wrong, one for correct, two for beating eager, three for also beating torch.compile. CUDA-L1 normalizes the reward and clips it at 1.5. I'd also measure on a dedicated GPU in random order, take the median, and re-check any sudden jump, since that is often a hack.

三家的 reward

三家的形状相同。先看正确性，不正确给 0 或负分，正确了再按 speedup 加分。PPO 和 GRPO 的原理见 RLHF、DPO、GRPO，这里只讲 reward。

手算两个例子

Kevin 的多轮 reward。一条 trajectory 有 3 步。第 1 步的 kernel 不正确，得 0。第 2 步正确，speedup 是 1.0，得 1.3。第 3 步的 speedup 是 1.5，得 1.8。这组数字是示意。

\[ R_3 = 1.8,\qquad R_2 = 1.3 + 0.4 \times 1.8 = 2.02 \] \[ R_1 = 0 + 0.4 \times 1.3 + 0.4^2 \times 1.8 = 0.808 \]

第 1 步自己是错的，但后面改对了，所以它也拿到 0.808。

CUDA Agent 的档位。一个 kernel 正确，比 eager 快 8%，比 torch.compile 慢 3%，得 2。再看 outlier。假设容易的 kernel 快 20 倍，难的 kernel 快 1.3 倍。用原始 speedup 当 reward，前者约是后者的 15 倍，gradient 被它带着走。离散档位下两者都是 3。CUDA Agent 的 ablation 把 reward 换回原始 speedup 后，对 torch.compile 的 faster rate 从 96.8% 掉到 60.4%，geomean 从 2.11x 掉到 1.25x。

防 hack 和降噪

  • 正确但没提速只给低分，CUDA Agent 给 1。Dr. Kernel 用 profiling-based reward 处理这种 lazy optimization
  • reward 突然跳高就复查。CUDA-L1 让 DeepSeek-R1 当 adversarial judge（手法和防御见 reward hacking）
  • 测量要降噪：独占 GPU，随机顺序跑 reference 和 candidate，取 median。CUDA-L1 把超过 3x 的结果放到第二张 GPU 上复测，相差 10% 以内才算

必答点

  • 基本形状：不正确给 0 或负分，正确了再按 speedup 加分
  • Kevin：0.3 + speedup，多轮用 γ = 0.4 的 discounted sum
  • CUDA Agent：离散的 −1、1、2、3，比原始 speedup 好，因为原始值有 outlier、偏向简单 kernel
  • CUDA-L1：normalize 后 clip 到 ±1.5
  • reward 的测量要降噪：独占 GPU、随机顺序、取 median
  • reward 突然跳高，先当 hack 查

追问

γ = 0.4 是什么意思？为什么用 sum 不用 max？

后一步的得分打 4 折，再后一步打 1.6 折，所以主要看自己和紧接着的一步。Kevin 的 ablation 里 sum 比 max 好。

GRPO 用在多轮上有什么问题？

Dr. Kernel 发现 GRPO 的 self-inclusion 会让 policy gradient 有偏，提出 TRLOO（turn-level leave-one-out）。GRPO 的公式见 GRPO。

训练时模型学会过哪些 hack？

Kevin 上有三种。第一种是直接复制 PyTorch reference。第二种是用 try-except 包住错的 CUDA kernel，失败就退回 PyTorch。第三种是继承 reference，不写 CUDA。对策是更严的 format check，用了 PyTorch function 或没有 CUDA kernel 的回答给 0 分。

RL 训练为什么不稳，怎么稳住？

CUDA Agent 最初只稳定训练了 17 步就崩了。它先做 single-turn 的 PPO warmup，再对 actor 做 RFT、对 critic 做 value pretraining，之后才做 agentic PPO。

还有别的 reward 形状吗？

Makora 用 logistic 函数，不正确为 0，否则是\(\sigma(\text{validated} + \max(0, \text{speedup}) - 1.8)\)。TritonRL 把 speedup clip 在 2，并且把 reasoning token 和 code token 的奖励分开给。
