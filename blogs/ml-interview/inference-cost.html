怎么降低 LLM 的 inference cost
和 token 用量？

英文问法How would you reduce LLM inference cost and latency? · How do you reduce prompt token usage? · How does speculative decoding work? · Why does quantization speed up decoding?

考过面经：微软 Teams AS IC2 的设计题（"reducing prompt token usage"）· 微软印度 IDC AS II（降 cost、降 inference latency）

先弄清楚：每个概念是什么

Prefill 与 decode
prefill 一次读完整个 prompt，矩阵乘矩阵，算力吃满（compute-bound）；decode 每步只出一个 token，却要把全部 weight 从显存搬一遍（memory-bound）。像读题一眼扫完，答案却一个字一个字写，每写一个字都要翻一遍整本书。例：7B 模型 fp16 weight 14 GB，显存带宽 1 TB/s → batch = 1 时每 token 至少 14 ms，最多约 70 token/s。
Quantization
weight 用更少的 bit 存：INT8、INT4（怎么量化见 INT8 quantization）。decode 主要在搬 weight，搬得少就快，也省显存。例：7B 从 fp16 的 14 GB 降到 INT4 的 3.5 GB，每 token 下限从 14 ms 降到 3.5 ms。
Continuous batching
按 iteration 调度：每生成一步，做完的请求离开，新请求马上补进来，不用等整批结束。像公交车每站上下客，而不是等全车人到终点才发下一班。读一次 weight 服务一整批请求，throughput 上去。
Prompt / prefix caching
很多请求开头一样（system prompt、few-shot、tool 定义），这段的 KV cache 算一次存起来，后面的请求直接复用，只算新增部分。例：Anthropic API 命中 cache 的 input token 默认按 0.1× 价格计费。
Speculative decoding
小 draft model 先猜 \(\gamma\) 个 token，大模型一次 forward 并行验证，猜对的都收下。像实习生先写草稿，主管一次批改。输出分布和只用大模型完全一样。

30 秒回答

I'd measure cost and latency at fixed quality, then pull three levers. Tokens: trim the system prompt and few-shot examples, summarize long history, retrieve only the top chunks, cap output length, and put the static prefix first so prompt caching can reuse it. Model: route easy queries to a smaller model, distill, and quantize weights to INT8 or INT4, which speeds up decoding because decoding is memory-bandwidth-bound. Serving: KV cache, continuous batching with PagedAttention for throughput, prefix caching for shared system prompts, and speculative decoding, where a small draft model proposes several tokens and the large model verifies them in one pass without changing the output distribution.

手算例子：7B 模型的显存和速度

  • weight：fp16 是 \(7\times10^9\times 2\) B = 14 GB；INT8 7 GB；INT4 3.5 GB（每 128 个 weight 再存一个 fp16 scale，约 3.6 GB）。
  • decode 下限（batch = 1，每个 token 读一遍 weight，带宽 1 TB/s）：fp16 14 ms/token（约 71 token/s），INT4 3.5 ms（约 285 token/s）。
  • KV cache：LLaMA-7B 每 token 512 KiB（怎么算），4096 context × batch 8 = 16 GiB，比 weight 还大，batch size 被它卡住。

推导 / 关键公式：speculative decoding

\(\alpha\) = draft token 被接受的平均概率，\(c\) = draft 与大模型单次 forward 的耗时比：

\[ \mathbb{E}[\#\text{tokens per run}] = \frac{1-\alpha^{\gamma+1}}{1-\alpha} \] \[ \text{speedup} = \frac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c+1)} \]

例：\(\alpha = 0.8\)、\(\gamma = 4\)、\(c = 0.05\)：大模型每跑一次平均产出 3.36 个 token，加速 \(3.36/1.2 = 2.8\times\)。代价：被拒的 token 白算，大模型总 FLOPs 约多 49%。

必答点

  • 先定指标：quality 不降的前提下比 cost、latency（首 token 时间、每 token 时间）、throughput
  • 三层 lever：token / model / serving
  • decode 是 memory-bound → quantization、batching 有效；prefill 是 compute-bound
  • KV cache 显存卡住 batch size → GQA、PagedAttention
  • speculative decoding 降 latency、不改输出分布，但不省 FLOPs

追问

continuous batching 为什么能提高 throughput？

static batching 要等整批里最长的请求结束，短请求的位置空转，还要 padding；按 iteration 调度每步都能换人。vLLM 再用 PagedAttention 像 OS 分页一样按 block 管 KV cache，显存接近零浪费，throughput 提高 2–4×（见 KV cache）。

speculative decoding 为什么不改变输出分布？

draft 给出 token \(x\)：\(q(x) \le p(x)\) 直接接受；否则以 \(1 - p(x)/q(x)\) 的概率拒绝，并从 \(\mathrm{norm}(\max(0, p - q))\) 重新采样，可以证明结果仍服从 \(p\)。\(\alpha\) 低，或 batch 已经大到 GPU 没有空闲算力时，就不划算。

prompt caching 怎么用才能命中？

只复用完全相同的前缀，所以 tools、system prompt、few-shot 放最前，user input、时间戳放后面。Anthropic API：5 分钟 cache 写入按 1.25× 计费，读取 0.1×（个别新模型更低）。vLLM 把共享前缀的 KV block 预先存好，prefill 只算 user input。

W8A8 还是 W4A16？

W8A8 把 weight 和 activation 都压成 INT8，矩阵乘本身变快，适合 prefill、大 batch；W4A16 只压 weight，省显存，主要加速 memory-bound 的 decode。bit 越低，直接 round-to-nearest 掉点越多（Llama-2-7B perplexity：FP16 5.47，INT4 5.73，INT3 6.66），所以用 GPTQ（用 Hessian 信息逐列量化，并更新还没量化的 weight 来补偿误差）或 AWQ（按 activation 找出约 1% 的 salient channel，放大后再量化），INT4 AWQ 是 5.60。

routing / cascade 怎么做？

FrugalGPT：先让便宜模型回答，scorer 给答案打分，低于阈值再交给更贵的模型。论文里在达到 GPT-4 同等效果时，cost 最多降 98%。
