GPU memory hierarchy 是怎样的？
一个 block 最多多少 thread？

英文问法Walk me through the GPU memory hierarchy. · How is shared memory (SRAM) different from HBM? · What's the maximum number of threads per block? · What is occupancy?

考过面经：NVIDIA DevTech NG 2026（"GPU 内存架构 SRM HBM区别"、"最高多少thread"，1p3a 1161658）；国内：NVIDIA 中国 AI Developer 一面（"GPU上的存储, global memory, local memory, shared memory, register的大小, 带宽, 访存延迟大概是在什么级别"）

先弄清楚：每个概念是什么

SM 与 grid / block / warp
GPU 由很多 SM（Streaming Multiprocessor）组成。kernel 启动成一个 grid，grid 拆成 block，每个 block 整个放在一个 SM 上跑。block 里每 32 个 thread 是一个 warp，同时执行同一条指令。像工厂有很多车间（SM），订单拆成工单（block），一张工单只交给一个车间，车间里 32 人一班（warp）同步干活。warp 和 SIMT 见 GPU vs CPU。
Register
每个 thread 私有，在 SM 上，最快。访问通常不加额外 cycle。由 compiler 分配，用太多就 spill 到 local memory。例：每个 SM 64K 个 32-bit register（256 KB），每个 thread 最多 255 个。
Shared memory 与 L1（SRAM）
每个 SM 上有一块 SRAM（unified data cache），一部分划给 shared memory，剩下当 L1 cache。shared memory 是程序员自己管的 scratchpad，同一个 block 的 thread 共享，像车间里的工作台。例：H100 每 SM 共 256 KB，其中 shared memory 最多 228 KB，一个 block 最多用 227 KB。
L2 与 HBM（global memory）
L2 在芯片上、所有 SM 共享；HBM 是片外显存，所有 thread 和 host 都能访问，大但远，像城外的仓库。local memory 名字叫 local，其实也在 HBM 上。例：H100 的 L2 50 MB；HBM 80 GB、3.35 TB/s（H100 SXM）。
Occupancy
SM 上活跃的 warp 数 ÷ 最多能放的 warp 数。warp 越多，一个在等内存时就越容易换另一个上来算，latency 就藏住了。例：每 block 768 thread，一个 SM 最多 2048 thread → 只放得下 2 个 block → 1536/2048 = 75%。

30 秒回答

From fastest to slowest: per-thread registers, 64K per SM. Each SM has 256 KB of on-chip SRAM on H100, split between L1 and shared memory, a programmer-managed scratchpad shared by a thread block. L2 is on chip and shared by all SMs, 50 MB. Global memory is off-chip HBM, 80 GB at about 3.35 TB/s, with hundreds of cycles of latency; local memory for register spills lives there too. A block has at most 1024 threads and runs on one SM, threads run in 32-wide warps, and an SM holds at most 2048 threads. Fast kernels reuse data in SRAM and registers and keep enough warps resident to hide latency.

受三样东西限制，取最紧的那个：thread 数（block 数）、register、shared memory。例：每 thread 64 个 register → 65536/64 = 1024 thread → 50%；每 block 100 KB shared memory → 一个 SM 只放 2 个 block。

必答点

  • 从快到慢：register → shared memory / L1（SM 上 SRAM）→ L2（全卡共享）→ HBM（global、local）
  • SRAM vs HBM：片上、每 SM 几百 KB、几十 cycle、程序员管 vs 片外、几十 GB、几百 cycle
  • block ≤ 1024 thread；warp = 32；H100 每 SM ≤ 2048 thread、≤ 32 block
  • occupancy = active warps / max warps，被 thread、register、shared memory 限制
  • 优化：数据搬进 shared memory / register 复用（GEMM tiling、FlashAttention），保证足够多 warp 藏 latency

追问

"最多多少 thread" 到底指什么？

分三个数：一个 block ≤ 1024；一个 SM 同时驻留 ≤ 2048（H100）；整张卡同时驻留 = SM 数 × 2048。一次 launch 的 grid 可以远大于此（x 方向最多 \(2^{31}-1\) 个 block），没轮到的 block 排队等 SM 空出来。

带宽大概多少？

H800 实测：shared memory 每 SM 每 cycle 128 bytes，按 114 个 SM、1755 MHz 算全卡约 26 TB/s；L2 约是 HBM 的 4 倍；HBM 实测约 1.9 TB/s（H100 SXM 标称 3.35 TB/s）。所以要尽量在 SRAM 里复用数据。

occupancy 越高越好吗？

不一定。occupancy 只是为了藏 latency，超过某个点就不再变快。每个 thread 多用 register、多算几个元素（ILP 高）时，低 occupancy 也能藏住。block size 取 32 的倍数，128–256 起步试。

register 用多了会怎样？

占满 register file 会压低 occupancy。超过 255 个或用 -maxrregcount 压低时会 spill 到 local memory，而它在 HBM 上，速度和 global memory 一样慢。

shared memory 和 L1 怎么分？怎么用？

同一块 SRAM，比例（carveout）可配，H100 的 shared memory 可选 0–228 KB。L1 由硬件自动 cache；shared memory 要自己读写，block 内用 __syncthreads() 同步。一个 block 要超过 48 KB 必须用 dynamic shared memory 显式 opt-in。32 个 bank，访问冲突见 bank conflict。
