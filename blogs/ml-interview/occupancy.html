Occupancy 受什么限制？
是不是越高越好？

先弄清楚：每个概念是什么

Occupancy
SM 上活跃的 warp 数，除以这个 SM 最多能放的 warp 数。像车间里开工的班组占工位的比例。H100 的一个 SM 最多放 64 个 warp，放了 32 个就是 50%。
Latency hiding
一个 warp 在等 memory 时，SM 切到别的 warp 继续发指令。warp 越多，越不容易全都在等。
Register file
每个 SM 有 65,536 个 register，SM 上所有 thread 一起分。每个 thread 用得越多，放得下的 thread 越少。
Limiter
register、shared memory、thread 数三个上限里最紧的那个。occupancy 由它决定。
Register spill
register 不够用时，compiler 把值放到 local memory。local memory 在 HBM 上，和 global memory 一样慢。

30 秒回答

Occupancy is the number of active warps on an SM divided by the maximum it can hold. It matters because when one warp is waiting on memory, the SM switches to another, which hides the latency. It's capped by whichever runs out first: registers per thread, shared memory per block, or the block size. Higher isn't always better. Once there are enough warps to keep the SM busy, more don't help, and squeezing registers to get there can cause spills. A GEMM that gives each thread more registers to reuse data often runs faster at lower occupancy. So low occupancy is a warning sign, but I judge by measured time.

三个上限，手算一遍

H100 的一个 SM 最多放 2,048 个 thread（64 个 warp），有 65,536 个 register 和最多 228 KB shared memory（见 thread 上限）。图里的 kernel 这样算。

  • thread 数：2,048 ÷ 256 = 8 个 block
  • register：一个 block 要 256 × 48 = 12,288 个，65,536 ÷ 12,288 取整是 5 个 block
  • shared memory：228 ÷ 48 取整是 4 个 block

取最小的 4 个 block，也就是 32 个 warp，occupancy 是 32 ÷ 64 = 50%。把每个 block 的 shared memory 减到 32 KB，这一项放宽到 7 个 block。这时 limiter 换成 register，能放 5 个 block，occupancy 是 62.5%。要到 100%，每个 thread 最多用 65,536 ÷ 2,048 = 32 个 register。

是不是越高越好

不是。occupancy 太低一定不好，够用之后再高没有收益，硬提上去还可能更慢。

  1. 它的作用只是 latency hiding。warp 已经多到 SM 每个 cycle 都有指令可发，再加也不会更快。NVIDIA 的文档说从 66% 提到 100% 通常得不到成比例的加速
  2. 提高它的办法是压 register 或 shared memory。register 压过头会 spill，shared memory 小了 tile 就小，数据复用变少
  3. GEMM 反过来做。每个 thread 多占 register，一次算一小块，occupancy 低了，实际更快（见 matmul 的 register tiling）
要做的事办法
看 occupancy 和 limiterncu 的 Occupancy 一节，报 theoretical 和 achieved occupancy，以及被 register、shared memory、thread 数里的哪个限制
看 register 用量编译时加 -Xptxas -v；ncu 的 Launch Statistics 也报每个 thread 的 register 数
调__launch_bounds__ 限制 register；block size 取 32 的倍数，从 128 到 256 试起；每个 block 少用 shared memory

必答点

  • 定义：SM 上活跃的 warp 数 ÷ 最多能放的 warp 数
  • 作用是 latency hiding，一个 warp 等 memory 时切到别的 warp
  • 三个上限取最紧的：register、shared memory、thread 数
  • 不是越高越好：够用之后没有收益；压 register 会 spill；GEMM 用低 occupancy 换 register 里的数据复用
  • 怎么看：ncu 的 achieved occupancy 和 limiter，-Xptxas -v 看 register
  • 怎么调：__launch_bounds__、block size、shared memory

追问

怎么知道 occupancy 是不是这个 kernel 的瓶颈？

在 ncu 里 memory 和 compute throughput 都低、warp 大量时间在 stall 时才怀疑它（见 Nsight profiling）。NVIDIA 的文档还给了一个试法：kernel 不改，把 dynamic shared memory 调大，人为压低 occupancy，看时间变不变。

__launch_bounds__ 是什么意思？

写在 kernel 上的声明，告诉 compiler 每个 block 最多多少 thread，还可以加上每个 SM 至少放几个 block。compiler 据此限制 register 用量。快手校招问过 launch bound 的含义，出处是 AIInfraGuide 的二手整理。

block size 越大，occupancy 越高吗？

不是。block 是整个放进 SM 的，block 越大，放不进下一个时空出来的位置越多。只看 register 这一项，上面 256 个 thread 的 block 能放 5 个，是 40 个 warp。换成 512 个 thread 的 block 只放得下 2 个，是 32 个 warp，反而更低。

fusion 之后 occupancy 掉了怎么办？

先看时间有没有变慢，没有就不用管。变慢了再看 limiter 是 register 还是 shared memory，决定是拆开一部分还是减少占用（见 kernel fusion）。

kernel agent 会用到 occupancy 吗？

会。Meta 的 KernelAgent 在 Diagnose 一步用 ncu 指标把 kernel 判成 memory、compute 或 occupancy bound，再选对应的优化（见 kernel agent 设计）。
