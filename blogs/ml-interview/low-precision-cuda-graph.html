MXFP8、NVFP4 训练时哪些用低精度，哪些留 FP32？
full-iteration CUDA Graph 为什么 dense 可以、MoE 难？

英文问法Where does Megatron use low precision in training, and which tensors stay in FP32? · Can the communication be quantized too? · Why can a dense model's whole training iteration go into one CUDA Graph, while MoE is hard?

考过推断，没有面经问过，依据是团队最近的 release notes 和 PR。

先弄清楚：每个概念是什么

MXFP8 和 NVFP4
Blackwell 上的两种低精度格式，元素分别是 8 bit 和 4 bit，都按 block 配 scale（格式见 mixed precision）。
Full-iteration CUDA Graph
把一整个 training iteration 录成一个 graph，之后每步一次 replay（见 CUDA Graph）。

30 秒回答

Megatron has MXFP8 and NVFP4 training paths. Not every tensor goes low-precision: selected parameters stay in FP32, and the output logits can too, because rounding them to BF16 before cross entropy loses bits you can't recover. Communication is quantized as well: FSDP gathers MXFP8 parameters directly, and NCCL EP can dispatch in MXFP8. A whole dense iteration can be captured in one CUDA Graph, I think because every step launches the same kernels with the same buffer sizes. MoE is harder: expert-dispatch buffers depend on routing, so they aren't capture-safe. The fix is a fixed receive budget. A step that overflows it is rerun once without dropping tokens.

低精度改了什么，哪些留在高精度

哪部分怎么做
计算GEMM 用 MXFP8 或 NVFP4 算。optimizer 仍然更新高精度的 master weight（见 mixed precision）
留在 FP32Selective FP32：打了标记的参数在模块转成低精度时留在 FP32，optimizer 和 checkpoint 跟着处理。LM output logits 也可选用 FP32 算
通信Quantized parameter gather：weight 是 MXFP8 时 FSDP 直接 all-gather 它的 data 和 scale，不先还原成高精度。NCCL EP 的 dispatch forward 和 combine backward 也能用 MXFP8

logits 留 FP32，是因为原来的 output layer 内部用 FP32 累加，但每个 logit 在 cross entropy 之前被舍成 BF16，丢掉的 bit 找不回来。代价是这一步的 kernel 慢一些。

按格式手算通信量。MXFP8 每个元素 8 bit，每 32 个元素再加一个 8 bit 的 scale，合 8.25 bit，约是 BF16 的 52%。NVFP4 每 16 个元素一个 scale，是 4 + 8/16 = 4.5 bit，约 28%。

Full-iteration CUDA Graph：dense 可以，MoE 难

CUDA Graph 要求每次 replay 的 kernel 序列、shape 和内存地址都不变（见 限制）。MFSDP v2 能把整个 iteration capture 下来再 replay，但只覆盖 dense 配置。MoE 被有意排除，理由是 MoE 的 "data-dependent expert-dispatch buffers are not capture-safe"。

dense 为什么可以，是按 CUDA Graph 的限制推出来的。batch 和 sequence length 固定时，每个 iteration 发的 kernel 和用的 buffer 都一样。

对策是固定 budget，NCCL EP 的 static mode 就是这样做的。溢出的那一步用 dropless 方式重跑一次（细节见 eager 和 static）。

必答点

  • MXFP8、NVFP4 都按 block 配 scale
  • 不是整个模型都低精度，有 selective FP32，output logits 可选 FP32
  • 通信也量化：quantized parameter gather，NCCL EP 的 MXFP8 dispatch
  • dense 每个 iteration 的 kernel 和 buffer 都一样，能整个 capture。MoE 的 dispatch buffer 随数据变，capture 不了
  • 对策是固定 budget，溢出的那一步用 dropless 方式重跑

追问

低精度一定更快吗？

不一定。NeMo-RL 跑 NVFP4 时 rollout 和 end-to-end 都比 BF16 快，training throughput 却比 BF16 慢，refit 也更慢。那时 backward 走 Transformer Engine 的 dequantized path，但没有说明这就是变慢的原因。

NeMo-RL 的 NVFP4 训练里，哪些部分没有量化？

只有 routed expert 的 MLP 在 forward 里用 NVFP4。持久保存的 weight、refit 传的数据、attention、router、shared expert 和部分 boundary layer 留 BF16，optimizer state 留 FP32。

低精度的 checkpoint 要注意什么？

加载时 quantized tensor 逐步 dequantize，不用给整个模型分配 BF16 的临时空间。要求 bit-exact 时，保留一份 full-precision 的 source of truth，并让重建路径完全一致（见 bitwise determinism）。
