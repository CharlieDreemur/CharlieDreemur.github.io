CNN 为什么适合图像？
输出尺寸和参数量怎么算？

英文问法Why use convolutions instead of fully connected layers for images? · What's the output size and parameter count of this conv layer? · Walk me through the classic CNN architectures.

考过微软 Teams AS IC2（“CNN architectures”）· Unity Montreal MLE NG 2019 店面（1p3a 533922）。手写 conv2d 见 ml-coding。

先弄清楚：每个概念是什么

Convolution
拿一个小窗口（kernel）在图上滑，每个位置和底下的像素对应相乘再求和，像拿一枚印章逐格比对，看哪里最像。库里其实不翻转 kernel，严格说是 cross-correlation。例：输入 0, 0, 1, 1（左暗右亮），kernel (−1, 1) → 0, 1, 0：只在明暗交界处亮，这就是 edge detector。
Local connectivity 与 parameter sharing
每个输出只看 k×k 的一小块；同一个 kernel 在所有位置复用，"找竖线"的规则在哪儿都一样。所以参数量和图片大小无关。例：32×32×3 → 32×32×16，FC 要约 5000 万个 weight，3×3 conv 只要 448 个参数。
Stride 与 padding
Stride 是每次挪几格，stride 2 让边长约减半；padding 是四周补 0，让边缘也被扫到。例：3×3 kernel、padding 1、stride 1，输出和输入一样大（"same" padding）。
Pooling
每个小窗口只留一个数（max 或 average），尺寸变小，没有参数。例：2×2 max pooling，窗口 (1, 3; 2, 0) → 3。
Equivariance 与 invariance
猫往右挪 2 格，conv 输出的 feature map 也往右挪 2 格（equivariance：跟着变）；再 pooling，小的平移基本不改变输出（invariance：不变）。

30 秒回答

Images have local structure, and the same pattern can appear anywhere. Conv layers exploit this with local connectivity, where each output sees only a k-by-k window, and parameter sharing, where one kernel slides over every position. So a layer has (k²·C_in + 1)·C_out parameters regardless of image size, and it's translation equivariant; pooling adds invariance to small shifts. The output size is floor((n + 2p − k)/s) + 1. Architectures went from AlexNet to VGG's stacked 3×3 convs, Inception's 1×1 bottlenecks, ResNet's residual connections that make very deep nets trainable, MobileNet's depthwise separable convs, and ViT, a Transformer on image patches.

关键公式

\[ n_{\text{out}} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1 \]

\(n\) 输入边长，\(k\) kernel 大小，\(p\) 每边 padding，\(s\) stride；stride 1 时 \(p = (k-1)/2\) 尺寸不变。

\[ \text{params} = (k^2 C_{\text{in}} + 1)\, C_{\text{out}} \]

每个输出 channel 一个 \(C_{\text{in}}\times k\times k\) 的 kernel 加一个 bias，和 \(n\) 无关。

手算例子：一个小 CNN 逐层算

尺寸按公式逐层往下推，参数只有 conv 和 FC 有。输入 32×32×3：

层设置输出尺寸参数量
conv116 个 5×5，s = 1，p = 0(32 − 5)/1 + 1 = 28 → 28×28×16(5·5·3 + 1)·16 = 1216
max pool2×2，s = 2(28 − 2)/2 + 1 = 14 → 14×14×160
conv232 个 3×3，s = 2，p = 1⌊13/2⌋ + 1 = 7 → 7×7×32(3·3·16 + 1)·32 = 4640
FC1568 → 10 类10(1568 + 1)·10 = 15690

共 21,546 个参数，最后的 FC 占七成多。AlexNet 的 60M 参数也主要在 FC 层。

经典架构（各一句）

架构关键点
AlexNet（2012）比 LeNet 深，ReLU、dropout、GPU；ImageNet top-5 error 26% → 15%
VGG全用 3×3 conv 堆叠：参数更少、非线性更多
Inception一个 block 并行跑多种 kernel 再拼接，先用 1×1 conv 降 channel

必答点

  • local connectivity + parameter sharing → 参数少，与图片大小无关
  • conv 是 translation equivariant；pooling 带来对小平移的 invariance
  • 输出尺寸 \(\lfloor (n+2p-k)/s \rfloor + 1\)；参数量 \((k^2C_{\text{in}}+1)\,C_{\text{out}}\)
  • 架构主线：AlexNet → VGG → Inception → ResNet → MobileNet → ViT

追问

VGG 为什么全用 3×3？

三个 3×3 叠起来的 receptive field 等于一个 7×7，参数 \(27C^2\) 对 \(49C^2\)，中间还多了两层 ReLU（VGG §2.3）。

1×1 conv 有什么用？

相当于在每个像素上做同一个 FC，只混合 channel，参数 \(C_{\text{in}}C_{\text{out}}\)。用来改 channel 数，比如 Inception 在大 kernel 之前先降 channel 省计算。

一层 conv 的计算量怎么算？

每个输出元素做 \(k^2C_{\text{in}}\) 次乘加，共 \(n_{\text{out}}^2 k^2 C_{\text{in}} C_{\text{out}}\) 次（MACs），FLOPs 约是它的 2 倍。上表 conv1：\(28^2\cdot 25\cdot 3\cdot 16 = 940{,}800\)。

ResNet 为什么能训很深？

每个 block 只学 residual \(F\)，\(F = 0\) 就是 identity，加深至少不比浅的差。gradient 还能沿 skip connection 直接传回前面的层，缓解 vanishing gradient。

CNN 和 ViT 怎么选？

CNN 自带 locality 和 translation equivariance 的 inductive bias，数据少时更好；ViT 只在 ImageNet 上训会比同等大小的 ResNet 差几个点，在 14M–300M 张图上 pre-train 后才追平或超过。
