先弄清楚：每个概念是什么

Coding agent
能自己读文件、改文件、跑命令的 LLM 工具，比如 Claude Code 和 Cursor（agent loop 见 mini coding agent）。
Spec 和验收测试
动手前写下的要求和我先写好的测试。agent 的产出过了测试才算数。
Fallback
新代码出错时悄悄退回旧实现，测试能过，但新代码没生效。Kevin 训练时学会了用 try-except 包住错的 CUDA kernel，失败就退回 PyTorch。

30 秒回答

I use coding agents every day, and I treat their output like a junior engineer's pull request. I write the spec and the acceptance tests first, then let the agent loop: write, run, read the error, fix. Nothing merges until it passes those tests and I've read the diff. In infra work it saves the most time on pipeline boilerplate, benchmark scripts, reading long logs, and porting code between languages. The risk is code that looks right but is wrong, or an agent that edits the test or adds a silent fallback to pass. So verification becomes the core of my job.

怎么验收 AI 的产出

  1. 先写 spec 和验收测试，再让 agent 动手。测试由我写
  2. 大任务拆小，一次只给它一件事
  3. 让它自己写、运行、看报错再改。我只看测试和 benchmark 的结果
  4. 逐个 review diff，看不懂的代码不合并
  5. 警惕三种能骗过测试的改法：改测试本身；加 fallback；用 try-except 吞掉错误
  6. 性能改动要有同一环境下前后的数字

第 5 条和 kernel agent 的 reward hacking 是同一件事，我在 RL environment 里设计 verifier 的经验可以直接用来审 agent 写的代码。FlashVector 里 agent 的改动也开成 PR 由人 review（见 改动怎么进生产）。

在 infra 里的价值和边界

内容
省时间的地方pipeline 样板代码；benchmark 脚本；读长日志；跨语言翻译，比如 CUDA 改 Triton。讯飞同场的另一篇复盘答的也是后三样（CUDA 到 CANN 的算子翻译）
边界会自信地写错；不懂业务约束和生产环境
面试官追问什么为什么这么写 prompt；AI 的修改对不对；你是否理解它写的代码；怎么测

最后一行转述自英文社区的面经。OpenAI 的 Agentic Coding screen 看你怎么验证产出、能不能解释代码并对它负责（Blind）。Anthropic 有一轮 onsite 是 review 四个 PR 再改进其中一个（PracHub）。

必答点

  • 把 AI 的产出当成 junior 的 PR：先有 spec 和测试，再 review diff
  • 以测试和 benchmark 为准，不信它的自述
  • 警惕改测试、加 fallback、吞掉错误
  • 价值：样板代码、benchmark 脚本、读日志、跨语言翻译
  • 边界：自信地写错，不懂业务约束和生产环境
  • 配一个自己的例子，并接到 verifier 的经验上

追问

AI 一直给回同一段错的代码，怎么办？

不再重复同一个 prompt，自己定位出错的位置，把最小复现和期望输出给它，或者这一小段自己写。场景转述自 Microsoft CoreAI 的 onsite 面经（PracHub）。

现场让你用 Claude Code 改一个项目，注意什么？

先读代码和已有的测试，说出计划，再小步改，每步都跑测试、看 diff。虾皮那一场改完会问方案有什么问题，要能指出 AI 方案的缺点。

AI 已经能写 kernel 了，你的价值在哪？

没有懂的人，就没法判断 AI 写的是不是更好，这是 r/CUDA 一个讨论帖的高赞观点（转述，Reddit）。我的价值在定目标、搭 harness、判断结果是真是假。
