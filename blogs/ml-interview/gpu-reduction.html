先弄清楚：每个概念是什么

Reduction
把一大堆数合成一个数，比如 sum、max、dot product。
Tree reduction
两两合并，每一步把还没合并的数减半，n 个数 \(\log_2 n\) 步做完。像淘汰赛，每一轮剩一半。
Warp shuffle
同一个 warp 的 32 个 thread 直接交换 register 里的值，指令是 __shfl_down_sync。它不经过 shared memory，也不用 __syncthreads。warp 和 shared memory 是什么见 GPU memory hierarchy。
atomicAdd
很多 thread 往同一个地址累加时，保证一个都不丢。谁先加谁后加不固定。

30 秒回答

I reduce in layers that follow the hardware. First, each thread adds up several elements as it loads them, so there is less left to combine. Then each warp does a tree reduction in registers with shuffle instructions: five steps for 32 lanes, with no shared memory and no syncthreads. Next, the warps in a block write their partial sums to shared memory and one warp reduces those. Finally the blocks combine with an atomic add or a second kernel. A sum is memory bound, so what matters most is reading at full bandwidth. One caveat: floating-point atomics add in a nondeterministic order, so the last bits can vary.

四层怎么分，手算一遍

对 \(2^{20}\) 个 float 求和。配置是示意的，128 个 block，每个 block 256 个 thread，一共 32,768 个 thread。

层做什么还剩几个数
thread每个 thread 边读边累加 32 个元素32,768
warpwarp shuffle 做 5 步，值只在 register 之间走1,024
block8 个 warp 的结果写进 shared memory，由一个 warp 再做 3 步128
grid128 个 block 用 atomicAdd 加到同一个地址，或者再 launch 一个 kernel1

warp 这一层的写法，执行完总和在 lane 0。

__device__ float warp_sum(float v) {
  for (int off = 16; off > 0; off /= 2)
    v += __shfl_down_sync(0xffffffff, v, off);
  return v;
}

求和每读 4 byte 只做 1 次加法，所以是 memory bound。优化的目标是把 memory bandwidth 用满，相邻 thread 要读相邻地址（见 coalescing）。Harris 的经典讲义在 G80 上对 4M 个 int 求和，分 7 步把 8.054 ms 优化到 0.268 ms，快 30 倍。

必答点

  • tree reduction：每步减半，\(\log_2 n\) 步
  • 分四层：thread → warp → block → grid
  • thread 先边读边累加多个元素
  • warp 内用 __shfl_down_sync，不用 shared memory 和 __syncthreads
  • warp 之间经过 shared memory，block 之间用 atomicAdd 或再 launch 一个 kernel
  • 浮点 atomicAdd 的累加顺序不固定，结果不完全确定

追问

shape 是 [M, N]，按行求和。M 很大怎么做，N 很大怎么做？

M 很大时每行分给一个 warp，一个 block 同时处理很多行。N 很大时一行拆给多个 block，每个 block 出一个 partial sum，最后合并。

结果和 CPU 上顺序相加的一样吗？

不一定。浮点加法换了顺序，末位会不同，atomicAdd 的顺序每次运行还可能不一样。验证时按 dtype 设容差，FlashVector 对改变浮点顺序的 rewrite 也是这样做的（见 kernel 正确性）。

grid 这一层，atomicAdd 和再 launch 一个 kernel 怎么选？

atomicAdd 写起来简单，代价是浮点结果不完全确定。再 launch 一个 kernel 时合并顺序是固定的，代价是多一次 launch。

warp 内为什么不用 shared memory？

shuffle 直接在 register 之间交换，省掉 shared memory 的读写和 __syncthreads。Harris 的老写法在 shared memory 里做，中间有一版还撞上 bank conflict。

reduction 前面还有 element-wise 运算怎么办？

融进同一个 kernel，边读边算边累加（见 kernel fusion）。FlashVector 的 Case 2 里，masked-mean pooling 拆成基本 op 后被 compiler 融成一个 Triton kernel。把它看成 reduction 的例子是推断。
