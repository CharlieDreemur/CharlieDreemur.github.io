Nemotron 3 Ultra 的 tech report：
550B 的 hybrid MoE 怎么训练、怎么 scale？

英文问法Walk me through how Nemotron 3 Ultra was trained and scaled. · What went wrong during pretraining, and how was it fixed? · Why a hybrid Mamba-attention MoE, and what does each choice cost?

考过没有面经，是你转述面试官说会考的团队自己的 report，训练用的就是 Megatron-LM 和 Megatron Core。

先弄清楚：每个概念是什么

Hybrid Mamba-2 + attention
层有 Mamba-2、attention、LatentMoE 三种，attention 只占少数。Mamba-2 每条序列只留一份固定大小的 state，attention 的 KV cache 每个 token 记一行。
LatentMoE
MoE 每个 token 的 compute 只跟 active parameter 走，550B 里只用到 55B。LatentMoE 的 expert 不在 model dimension 上算，在更小的 latent 里算。省下的 cost 换成更多 expert。
MTP（Multi-Token Prediction）
backbone 后面接的小 head，多预测后面几个 token。Ultra 的两个 head 共享参数，每个是一层 attention 加一层 MoE。训练时它是权重很小的 auxiliary loss，inference 时当 speculative decoding 的 drafter。
NVFP4
Blackwell 的 4-bit 浮点格式，元素是 E2M1（格式见 mixed precision、MXFP8 和 NVFP4）。Ultra 全程用它 pretrain。
MOPD
Multi-teacher On-Policy Distillation。student 自己生成 rollout，对应 domain 的 teacher 给每个 token 打分。

30 秒回答

Nemotron 3 Ultra is a 550-billion-parameter MoE with 55 billion active. Most layers are Mamba-2 or LatentMoE, with a few attention layers and shared multi-token-prediction heads. It was pretrained in NVFP4, with the final layers and sensitive projections kept in higher precision, and BF16 branches showed almost the same loss. Training diverged twice. First, output-layer gradients were accumulated in BF16, which rounded away the small MTP gradients. FP32 fixed it. The second was never explained, so they rolled back and decayed the learning rate early. A long-context phase used context and expert parallelism to reach one million tokens. Post-training was SFT, RL, multi-teacher distillation and a final MTP step.

Pretraining：NVFP4 怎么训

  • Kernel：Transformer Engine 的 cuBLAS NVFP4 GEMM，fprop、dgrad、wgrad 三个都用
  • Recipe：weight 做 2D block quantization，wgrad 的输入做 Random Hadamard Transform，gradient 用 stochastic rounding
  • 留高精度的部分：末尾一段层，几类敏感的 projection（Mamba output、latent、QKV 和 attention projection），MTP，embedding
  • 怎么确认没训坏：中途分几支换成全 BF16 再训一段，train loss 和 NVFP4 主线差得很少

两次 divergence

Divergence 1Divergence 2
现象loss 和 wgrad 的 L2 norm 一起涨，MTP-2 的 loss 最先 spikeloss 和 wgrad 的 L2 norm 一起涨
原因为了让 DP 的 gradient reduction 用 BF16 传来提 throughput，output layer 的 local gradient accumulation 从 FP32 降到了 BF16。MTP 的 loss 权重很小，BF16 只有 7 个 mantissa bit，MTP 给 shared output layer 的 wgrad 基本丢光没找到
修法回滚，恢复 FP32 的 gradient reduction回滚到 phase 2 开头，立刻 LR annealing，提前结束

Divergence 2 不是 NVFP4 造成的，换成全 BF16 的那一支同样 diverge。report 只列了两个相关现象，expert 负载越来越不均衡，residual norm 跨层差好几个数量级。

Long-context phase：扩到 1M

用 constant LR 做 continued pretraining，跑在 GB200 上。parallelism 用了 CP、TP、EP、PP（CP、怎么选配置）。CP 为了长序列，1M 的序列一个 rank 放不下。EP 为了 MoE，把 expert 分到不同 rank。大部分 iteration 用 1M。少数用短序列，只放 math 和 code 的 SFT-style 数据，保住短 benchmark。一个 iteration 不混两种长度。

架构选择和代价

选择换来什么代价
Mamba-2 换掉大部分 attentiondecode 每步的 cost 不随长度变，长输出时 throughput 高state 固定，context 短时反而比 KV cache 大（见下式）。speculative decoding 每个 draft step 要存一份 state 才能回滚
LatentMoE，很多 expert 选少数同样的 inference cost 下放更多 expertprefill FLOPs 跟 active parameter 走，比 17B active 的 Qwen-3.5 多约 55 / 17 ≈ 3.2 倍。长输入、短输出时 throughput 落后
MTP，head 共享参数single-user decode 和 RL rollout 都靠它做 speculative decoding 提速引出 divergence 1。large batch 下 verification 吃掉 throughput，常要调短或关掉
\[ L^{*} = \frac{\text{Mamba state size}}{\text{KV cache bytes per token}} \]

短于 \(L^{*}\) 时 state 比 KV cache 大。按 report 的数，state 是 384 MB（FP32，batch 1），FP8 KV cache 每 token 6,144 byte（按模型 shape 手算），\(L^{*} = 384\ \text{MB} \div 6144\ \text{B} = 65{,}536\)，即 64K。

Post-training 和 RL infra

  • 顺序：SFT → RLVR → MOPD warmup → MOPD → MTP Boosting
  • RLVR：asynchronous GRPO，每个 sample 采一组 rollout（GRPO 见 RLHF、DPO、GRPO）
  • MOPD：每个 domain 一个 teacher。SWE-Bench Verified 几乎追平 teacher，HLE 只追回一小部分
  • EP 对齐 NVLink domain：一个 NVL72 rack 是一个 NVLink domain。EP group 跨 rack 时 all-to-all 走 InfiniBand，对齐后 throughput 明显提高（见 EP communication）
  • Checkpoint：同步保存会卡住训练。换成 NVRx 的 async checkpoint 加 Megatron Core Distributed Optimizer 后几乎不阻塞（见 distributed optimizer）
  • 启动：cold init 很慢，缓存 JIT 产物后几乎不用等

  • 主 pretraining 的 parallelism 配置、GPU 数、batch size、sequence length、optimizer、throughput 和训练时长
  • long-context phase 的 DP size 和 GPU 总数
  • 留在 "higher precision" 的层具体是哪种精度
  • NVFP4 训练比 BF16 快多少

读 report 要小心的两处

  • headline 的 throughput 倍数只来自一个长输出 setting，Ultra 用 TRT-LLM 测，对手用 vLLM 测。abstract 和 conclusion 的倍数也对不上
  • 没有 attention-only 的对照，Mamba-2 单独贡献多少没有量过

必答点

  • 550B total、55B active，Mamba-2 和 LatentMoE 为主，少量 attention，MTP head 共享参数
  • NVFP4 pretraining，末尾一段层和几类 projection 留高精度，BF16 分支的 loss 几乎一样
  • Divergence 1：output layer 的 gradient accumulation 降到 BF16，丢了 MTP 的 wgrad，改回 FP32
  • Divergence 2：原因没找到，换 BF16 也一样，回滚后提前 decay LR
  • Long-context：CP 切长序列，EP 切 expert
  • 代价：短于 \(L^{*}\) 时 Mamba state 比 KV cache 大。prefill FLOPs 跟 active parameter 走

追问

BF16 的 accumulation 为什么会丢掉 MTP 的 gradient？

机制是推断。report 只给了两个事实，MTP 的 loss 权重很小，BF16 只有 7 个 mantissa bit。浮点加法先对齐 exponent，比累加值小约 \(2^{8} = 256\) 倍以上的增量落在 mantissa 之外，被舍掉（累加本身见 gradient accumulation）。

long-context phase 的四个 parallelism 各切什么？

CP 切序列，每个 rank 放 \(L / \text{CP}\) 个 token。这一段 CP = 32，1M 的序列每个 rank 放 32,768 个。TP 切 weight，EP 把一层的 expert 分到不同 rank，PP 切层。EP size 是 128，比一个 NVL72 的 72 张 GPU 多，所以 all-to-all 很可能跨了 NVLink domain。这是推断，report 没写这一段用的是不是 NVL72。

serving 时 wide TP 和 wide EP 怎么选？

small batch 受 weight read 的 memory bandwidth 限制，TP 越宽每个 rank 读的 weight 越少，所以 low latency 用 wide TP。large batch 的瓶颈是 activation 的通信，EP 只在 routed expert 前后各做一次 all-to-all，所以 high throughput 用 wide EP。prefill-heavy 的 workload 上，all-to-all 占了 runtime 的不小一部分。

Hopper 没有 FP4 tensor core，为什么还是只发一个 NVFP4 checkpoint？

FP8 的 checkpoint 几乎占满 8 张 H100 的 GPU memory，NVFP4 的小得多。FP8 那边每张卡留给 activation 和 cache 的空间很少，batch 上不去，workload 一直是 memory-bandwidth-bound，FP8 tensor core 的算力用不上。

MOPD 之前为什么要 warmup？为什么 HLE 涨得少？

teacher 和 student 用不同的 SFT 数据训出来，student 的 rollout 对 teacher 是 out-of-distribution，打分不可靠。先用 teacher 的数据做很轻的 SFT，GDPVal 就明显涨了。HLE 上 teacher 的优势来自 student 没见过的数据，student 很少采样到那些推理路径，所以 warmup 也帮不上。
