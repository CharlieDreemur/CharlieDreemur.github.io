Nemotron 3 Ultra 的 tech report：
550B 的 hybrid MoE 怎么训练、怎么 scale？

英文问法Walk me through how Nemotron 3 Ultra was trained and scaled. · What went wrong during pretraining, and how was it fixed? · Why a hybrid Mamba-attention MoE, and what does each choice cost?

考过还没有面经 · 团队自己的 2026 report（arXiv 2606.15007，2026-06，65 页），正文点名用了 Megatron-LM、Megatron 的 EP 和 Megatron Core Distributed Optimizer · 你转述面试官会考这篇（2026-11）· 下面每个数字都标了 report 的页码

先弄清楚：每个概念是什么

Hybrid Mamba-2 + attention
108 层，按 Figure 2 数是 48 层 Mamba-2、12 层 attention、48 层 LatentMoE。Mamba-2 每条序列只留一份固定大小的 state，attention 的 KV cache 每个 token 记一行。
LatentMoE
expert 不在 8192 维的 model dimension 上算，在 2048 维的 latent 里算。省下的 cost 换成更多 expert，每层 512 个里选 22 个（p.4、p.48）。
MTP（Multi-Token Prediction）
backbone 后面接的小 head，多预测后面几个 token。Ultra 的两个 head 共享参数，每个是一层 attention 加一层 MoE（p.3）。训练时它是 auxiliary loss，权重 0.1。inference 时它当 speculative decoding 的 drafter。
NVFP4
Blackwell 的 4-bit 浮点格式，元素是 E2M1（格式见 mixed precision、MXFP8 和 NVFP4）。Ultra 的 20T token 都用它训练。
MOPD
Multi-teacher On-Policy Distillation。student 自己生成 rollout，对应 domain 的 teacher 给每个 token 打分。

30 秒回答

Nemotron 3 Ultra is a 550-billion-parameter MoE with 55 billion active, mixing Mamba-2, sparse attention layers and LatentMoE. It was pretrained in NVFP4 on 20 trillion tokens, keeping the last 16 layers and sensitive projections in higher precision; the loss gap to BF16 stayed under 0.4 percent. Training diverged twice. First, output-layer gradients were accumulated in BF16, which dropped the small MTP gradients; FP32 fixed it. The second was never explained, so they decayed the learning rate early and stopped at 20 trillion. A 33-billion-token phase extended context to one million with CP 32, TP 8, EP 128, PP 2. Post-training was SFT, RL and multi-teacher distillation.

Pretraining：NVFP4 怎么训

  • Kernel：Transformer Engine 的 cuBLAS NVFP4 GEMM，fprop、dgrad、wgrad 三个都用（p.3）
  • Recipe：weight 做 2D block quantization，wgrad 的输入做 Random Hadamard Transform，gradient 用 stochastic rounding（p.3）
  • 留高精度的部分：最后 16 层（15%）、Mamba output projection、latent projection、QKV 和 attention projection、MTP、embedding（pp.3–4）
  • 怎么确认没训坏：在 5T、10T、16T 各分出一支，全部 tensor 换成 BF16 再训 74B token。relative train loss gap 平均低于 0.4%（p.4）

两次 divergence

Divergence 1，约 8TDivergence 2，约 16T
现象loss 和 wgrad 的 L2 norm 一起涨，MTP-2 的 loss 最先 spikeloss 和 wgrad 的 L2 norm 一起涨
原因为了让 DP 的 gradient reduction 用 BF16 传来提 throughput，output layer 的 local gradient accumulation 从 FP32 降到了 BF16。每个 MTP block 的 loss 权重只有 0.05，BF16 只有 7 个 mantissa bit，MTP 给 shared output layer 的 wgrad 基本丢光没找到
修法回滚，恢复 FP32 的 gradient reduction回滚到 15T 立刻开始 LR annealing，总量砍到 20T

两次都在 p.12。Divergence 2 不是 NVFP4 造成的，从 16T 起全部换成 BF16 的那一支同样 diverge（p.5）。report 只列了两个相关的现象。一个是 expert 失衡，第一层 MoE 的 MaxVio 从 4.8 涨到 12T 时的约 12，上限是 512 / 22 = 23.27（pp.13–14）。另一个是 residual norm 跨层差 4 个数量级，前几层从 7.5T 开始涨，11T 出现大 spike（p.14）。

Long-context phase：扩到 1M

33B token 的 continued pretraining，constant LR 2.5e-6，跑在 GB200 上。parallelism 是 CP 32 × TP 8 × EP 128 × PP 2（CP、怎么选配置）。每个 iteration 固定 25,165,824 token，除一下是 24 条 1M 的序列。92% 的 iteration 用 1M，8% 用 4K 并且只放 math 和 code 的 SFT-style 数据，用来保住短 benchmark。一个 iteration 里不混两种长度。base model 的 RULER 在 1M 是 76.83（p.9、p.10）。

Post-training 和 RL infra

  • 顺序：SFT → RLVR → MOPD warmup → MOPD 两轮 → MTP Boosting（p.15、p.20）
  • RLVR：asynchronous GRPO，global batch 8192，每个 sample 16 个 rollout（p.20，GRPO 见 RLHF、DPO、GRPO）
  • MOPD：10 个以上的 teacher。SWE-Bench Verified 从 RLVR 的 65.8 到 71.7，teacher 是 72.5。HLE 只追回 16.9% 的差距（p.27）
  • EP 对齐 NVLink domain：一个 NVL72 的 NVLink domain 是 72 张 GPU。EP group 跨 rack 时 all-to-all 走 InfiniBand，对齐后 end-to-end throughput 加 20%（pp.33–34，见 EP communication）
  • Checkpoint：同步保存每次卡 60 s 左右。NVRx 的 async checkpoint 加 Megatron Core Distributed Optimizer 之后不到 1 s（p.34，见 distributed optimizer）
  • 启动：1K GPU 的 cold init 从 38.8 min 降到 0.4 min，靠缓存 JIT 的产物（pp.34–35）

读 report 要小心的两处

  • 5.9× 只是 8K in / 64K out 这一个 setting。Ultra 用 TRT-LLM 测，对手用 vLLM 测（p.2）。abstract 写约 6×，conclusion 写 5×
  • 没有 attention-only 的对照，Mamba-2 单独贡献多少没有量过

必答点

  • 550B total、55B active，108 层，每层 512 个 expert 选 22 个
  • NVFP4 pretraining 20T token，最后 16 层和几类 projection 留高精度，loss gap 低于 0.4%
  • Divergence 1：output layer 的 gradient accumulation 降到 BF16，丢了 MTP 的 wgrad，改回 FP32
  • Divergence 2：原因没找到，换 BF16 也不解决，靠提前 decay LR 和砍到 20T 缓解
  • Long-context：33B token，CP 32 × TP 8 × EP 128 × PP 2，92% 的 iteration 是 1M
  • 代价：prefill 比 Qwen-3.5 慢，Mamba state 在短 context 下比 KV cache 大

追问

BF16 的 accumulation 为什么会丢掉 MTP 的 gradient？

机制是推断，report 只给了 0.05 和 7 个 mantissa bit 两个事实（p.12）。浮点加法先对齐 exponent，比累加值小 256 倍以上的增量落在 mantissa 之外，被舍掉（累加本身见 gradient accumulation）。

long-context phase 的四个 parallelism 各切什么？

CP 32 把 1M 的序列切成每个 rank 32,768 token，TP 8 切 weight，EP 128 让每个 rank 放 4 个 expert，PP 2 切层，数字是按 Table 1 除出来的。EP 128 比一个 NVL72 的 72 张 GPU 多，所以 all-to-all 很可能跨了 NVLink domain。这是推断，report 没写这一段用的是不是 NVL72。

serving 时 wide TP 和 wide EP 怎么选？

small batch 受 weight read 的 memory bandwidth 限制，TP 越宽每个 rank 读的 weight 越少，所以 low latency 用 wide TP。large batch 的瓶颈是 activation 的通信，EP 只在 routed expert 前后各做一次 all-to-all，所以 high throughput 用 wide EP（p.49）。all-to-all 在 prefill-heavy 的 workload 上占 15% 到 20% 的 runtime（p.50）。

Hopper 没有 FP4 tensor core，为什么还是只发一个 NVFP4 checkpoint？

8 张 H100 一共 640 GiB。FP8 的 checkpoint 约 540 GiB，每张卡只剩约 10 GiB 给 activation 和 cache。NVFP4 约 330 GiB，剩约 40 GiB（pp.45–46）。FP8 那边 batch 上不去，workload 一直是 memory-bandwidth-bound，FP8 tensor core 的算力用不上。

MOPD 之前为什么要 warmup？为什么 HLE 涨得少？

teacher 和 student 用不同的 SFT 数据训出来，student 的 rollout 对 teacher 是 out-of-distribution，打分不可靠。先用 teacher 的数据做很轻的 SFT，GDPVal 从 35.3 到 46.7（p.27）。HLE 上 teacher 的优势来自 student 没见过的数据，student 很少采样到那些推理路径，所以 warmup 也帮不上（p.28）。
