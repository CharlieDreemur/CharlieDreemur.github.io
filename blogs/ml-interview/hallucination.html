LLM 为什么会 hallucinate？
怎么避免？

英文问法How would you reduce hallucinations in an LLM application? · Why do LLMs hallucinate? · How do you detect hallucinations?

考过★ 作者本人微软 AS 电面 · 面经：微软中国 Bing LLM 应用组实习（RAG hallucination）· 微软 AS 实习电面问 LLM 部署的问题与解法（1p3a 1158834）· Interview Query 指南

先弄清楚：每个概念是什么

Hallucination
流畅、自信、但没有依据的内容。像考试不会也不留白，编一个看着像的答案。例：问一个不太出名的人的生日，同一个模型三次答了三个不同的日期。
Factuality vs faithfulness
factuality 错是和真实世界不符；faithfulness 错是和给它的 context、指令不符。RAG 场景主要防后者。答案必须被检索到的文档支持。例：说电话是 Edison 发明的 → factuality；摘要里出现原文没有的数字 → faithfulness。
Knowledge boundary（长尾知识）
训练数据里只见过一两次的事实记不牢，新发生的事根本没见过，但模型照样回答。例：如果 20% 的生日事实在训练数据里只出现一次，base model 至少会在约 20% 的生日问题上编。
Grounding 与 citation
要求只根据给定材料回答、每句标出处，材料里没有就说不知道。像开卷考试要求每句话标页码，阅卷人能逐条核对。
Self-consistency
同一个问题 sample 多次：真知道的，几次答案一致；编的，每次都不一样。可以对答案投票，也可以把不一致当成 hallucination 的信号（SelfCheckGPT）。

30 秒回答

A hallucination is fluent output that isn't supported: either factually wrong, or unfaithful to the context the model was given. Causes include noisy or outdated data, long-tail facts seen only once, training and benchmarks that reward a confident guess over "I don't know", and sampling randomness. I'd mitigate it in layers. Ground the model: retrieve documents with RAG, answer only from them with citations, and call tools for math or fresh data. Decode with a low temperature. Train abstention with SFT and RLHF data that reward saying "I don't know". Then verify: sample several answers and check consistency, run an NLI check against the sources, and track groundedness in evaluation.

推导：为什么模型宁可猜

设模型答对的把握是 \(c\)。0-1 打分（答对 1 分，答错和"不知道"都 0 分）下，猜的期望是 \(c \ge 0\)，永远不亏。大多数 benchmark 和 post-training 都按这种方式打分，模型就被训练成爱猜。改成答错扣 \(t/(1-t)\) 分：

\[ \mathbb{E}[\text{guess}] = c - (1-c)\,\frac{t}{1-t} \] \[ \mathbb{E}[\text{guess}] > 0 \iff c > t \]

例：\(c = 0.3\)。0-1 打分下猜得 0.3 分；\(t = 0.5\)（错一题扣 1 分）下猜得 \(0.3 - 0.7 = -0.4\)，应该说不知道。

怎么缓解：分层做

层做法针对
数据 / 训练data cleaning、更新数据；SFT 加"不知道就拒答"样本；RLHF 惩罚编造错误知识、不会拒答
GroundingRAG + citation；prompt 要求只据材料回答；tool（search、calculator、code）缺知识、知识过时
Decoding低 temperature 或 greedy抽到 tail 里的词
检测self-consistency；NLI 判断回答是否被 source 支持；数字、日期做 rule check；高风险加 human review前面漏掉的
评估TruthfulQA、FActScore、groundedness；打分时别惩罚"不知道"衡量和激励

必答点

  • 两类：factuality（和事实不符）vs faithfulness（和 context 不符）
  • 原因：data（噪声、过时、长尾）→ training（拒答没被教过，0-1 打分奖励猜）→ inference（sampling 随机性）
  • 缓解分层：RAG + citation、tool、低 temperature、拒答训练、RLHF
  • 检测：self-consistency、NLI verifier、human review；评估时别惩罚"不知道"

追问

用了 RAG 还会 hallucinate 吗？

会。检索不到或检索错。文档和模型自己的记忆冲突时模型信了记忆。context 太长时中间的信息被忽略（lost in the middle）。对策是 rerank、逐句 citation、用 NLI 检查每句话是否被文档支持，见 RAG。

没有标准答案时怎么检测？

SelfCheckGPT：同一个 prompt 多 sample 几次，某句话在其他 sample 里得不到支持就可疑，不需要外部数据库。有 source 时用 NLI 判断 source 是否 entail 这句话。

self-consistency 具体怎么做？

用 chain-of-thought sample 多条 reasoning path，对最终答案 majority vote。代价是 inference 成本乘以 sample 数。

RLHF 之后为什么还会编，甚至顺着用户说？

sycophancy：人类标注者和 reward model 都偏爱顺着用户的回答。RLHF 确实有用。InstructGPT 在 closed-domain 任务上的 hallucination 率从 GPT-3 的 41% 降到 21%，但不能根除。

temperature 设成 0 就不会 hallucinate 了吗？

不会。greedy 只去掉 sampling 的随机性；模型本来就记错或没见过的知识，照样会被当成最可能的答案输出。
