Amdahl's law 是什么？
对 distributed training 意味着什么？

英文问法Explain Amdahl's law. · If 90% of the work is parallelizable, what's the max speedup on 8 GPUs? · How is it different from Gustafson's law? · Why doesn't adding GPUs give linear speedup?

考过面经：NVIDIA DevTech NG 2026（1p3a 1161658）；其他公司：PracHub 上标为 NVIDIA SWE 的题（"Explain Amdahl's law and GPU matmul optimization"）

先弄清楚：每个概念是什么

Speedup
同一个任务，原来的时间 ÷ 现在的时间。例：10 s 变成 2 s，speedup = 5×。
可并行比例 \(p\)
原来的运行时间里，能被分给多个 worker（或被加速）的那一部分占多少；剩下的 \(1-p\) 只能一个人干。像搬家：搬箱子可以多叫人，但只有一辆车开过去那段路分不了。例：\(p = 0.9\)，10% 的时间永远是串行的。
Amdahl's law（strong scaling）
问题规模固定，worker 加到 \(N\) 个，串行部分一点没变，于是 speedup 被锁死在 \(1/(1-p)\)。
Gustafson's law（weak scaling）
问题规模随 \(N\) 一起变大，每个 worker 的活不变。串行部分不随规模增长，占比被稀释，speedup 接近线性。例：\(p = 0.9\)、\(N = 8\)：Amdahl 4.71×，Gustafson 7.3×。
Scaling efficiency
speedup ÷ \(N\)，加的卡有多少真的变成了速度。例：\(p = 0.9\)、\(N = 8\) → 4.71/8 = 59%。

30 秒回答

If a fraction p of the runtime is parallelized over N workers, Amdahl's law gives a speedup of 1 / ((1 − p) + p / N), capped at 1 / (1 − p) even with infinite workers. With p = 0.9, eight workers give 4.7× and the cap is 10×, so first attack the serial part. That's strong scaling, a fixed problem size. Gustafson's law is weak scaling: if the problem grows with N, the serial share shrinks and speedup is nearly linear. In distributed training, exposed communication, the pipeline bubble, data loading and stragglers are the serial part, so we overlap communication and grow the global batch with the GPU count.

推导 / 关键公式

原来时间记为 1，并行部分被 \(N\) 个 worker 分掉：

\[ T(N) = (1-p) + \frac{p}{N} \] \[ S(N) = \frac{1}{(1-p) + p/N} \;\xrightarrow{N\to\infty}\; \frac{1}{1-p} \]

Gustafson：在 \(N\) 个 worker 上测，串行时间占比为 \(1-p\)，同样的活一个 worker 要做 \(N\) 倍的并行部分：

\[ S = N + (1-p)(1-N) \]

手算例子

\(p = 0.9\)、\(N = 8\)：\(S = 1/(0.1 + 0.9/8) = 1/0.2125 = 4.71\)；\(N\to\infty\)：10。

串行部分从 10% 压到 1%，64 卡的 speedup 从 8.8× 变成 39×，比加卡管用得多。

放到 distributed training 里

  • "串行部分"是什么：没藏住的 communication（DP 的 all-reduce 每卡每步收发约 \(2\Psi\) 个元素，不随 \(N\) 变小）、pipeline bubble、data loading、等最慢的卡。
  • 例：单卡一个 step 1.0 s 全是计算；\(N\) 卡时计算 \(1/N\) s，另有 0.1 s 没 overlap 的 all-reduce。8 卡 0.225 s，4.4×；64 卡 8.6×；再加卡也到不了 10×。
  • 办法：communication 和 backward overlap，减小 exposed 部分；global batch 随卡数一起放大（weak scaling），每卡的计算量不变，串行占比就不涨。

必答点

  • \(S = 1/((1-p) + p/N)\)，上限 \(1/(1-p)\)
  • \(p = 0.9\)：8 卡 4.71×，无穷多卡也只有 10×
  • 先砍串行部分；\(N\) 大了以后加卡的边际收益很小
  • Gustafson：问题随 \(N\) 变大 → 接近线性（weak scaling）
  • 训练里的串行部分：exposed communication、bubble、data loading、straggler → overlap、放大 global batch

追问

Amdahl 和 Gustafson 矛盾吗？

不矛盾，问的问题不同：Amdahl 固定问题规模，问能快多少；Gustafson 固定运行时间，问能做多大的问题。Gustafson 在 1024 处理器上、串行占 0.4%–0.8% 的应用里测到 1016–1021 倍的 scaled speedup。大模型 pretrain 更像后者，因为卡多了就加大 batch 或模型。

实际 speedup 为什么常常比 Amdahl 预测的还低？

Amdahl 假设并行部分完美均分、没有额外开销。实际上 communication 随 \(N\) 增加（latency 项、跨机带宽更低）、负载不均、同步要等最慢的卡。TP 切得太细时 GEMM 变小，加卡甚至变慢（见 TP communication）。

怎么知道 \(p\) 是多少？

profile 一次（Nsight Systems、PyTorch profiler），看可并行部分占多少时间；或者用测到的 speedup 反推：\(p = (1 - 1/S)/(1 - 1/N)\)。例：8 卡测到 4.71× → \(p = 0.9\)。

和 GPU 加速有什么关系？

同一个公式，\(N\) 换成"这部分被加速了几倍"。matmul 搬到 GPU 快 50 倍，但只占 80% 时间：\(1/(0.2 + 0.8/50) = 4.6\times\)。剩下的 CPU 预处理、host↔device 拷贝、kernel launch 就成了瓶颈。

大规模训练实际 scaling 怎么样？

Megatron-LM 把模型和 batch 随卡数一起放大，8.3B 模型在 512 张 GPU 上做到 76% scaling efficiency（相对单卡）。这是 weak scaling。
