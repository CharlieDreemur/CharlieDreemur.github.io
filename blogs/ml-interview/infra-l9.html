Megatron Core 代码地图与 RL 训推

一个仓库，两样东西

  • Megatron Core（megatron/core/）：一个库，提供能自由组合的并行积木：attention、MLP 等 transformer 模块，TP、PP、DP、EP、CP，FP16、BF16、FP8、FP4。可以用 pip install megatron-core 单独安装
  • Megatron-LM：搭在 Core 上的参考训练脚本（根目录的 pretrain_gpt.py、megatron/training/），拿来就能跑
  • 打个比方：Core 是一套标准厨具加传菜规则，Megatron-LM 是用这套厨具写好的一本菜谱，别的团队也能用同一套厨具写自己的菜谱
  • 谁在用 Core：README 点名的是 Megatron Bridge（Hugging Face 和 Megatron 的 checkpoint 双向转换，加训练 recipe）；官方文档的 “Libraries using Megatron Core” 还列了 NeMo RL、NeMo Framework 和 Model Optimizer。仓库之外，verl 的训练端也能选 Megatron

parallel_state：给每张卡发一组坐标

Process group 是一组要一起做 collective 的 rank，像微信群：all-reduce 只在群里发，不会发给全公司。每张卡同时在一个 TP 群、一个 DP 群和一个 PP 群里。

例子：16 张卡（2 台机器 × 8），TP = 2、PP = 2，DP 由代码算出来：16 ÷ (2 × 2) = 4。initialize_model_parallel 的默认 order="tp-cp-ep-dp-pp"，越靠左变化越快。CP、EP 都是 1 时，就等于按 tp、dp、pp 的顺序编号：

\[ \text{rank} = \text{tp} + 2\cdot\text{dp} + 8\cdot\text{pp} \]

例：rank 5 = 1 + 2 × 2 + 8 × 0，坐标是 (tp 1, dp 2, pp 0)。它的 TP 搭档是 4，DP 群是 [1, 3, 5, 7]，PP 下一段是 13。

群个数 × 每群卡数成员在哪
TP8 × 2[0, 1] [2, 3] … [14, 15]相邻 rank，同一台机器，走 NVLink
DP4 × 4[0, 2, 4, 6] [1, 3, 5, 7] [8, 10, 12, 14] [9, 11, 13, 15]这个例子里也在机内
PP8 × 2[0, 8] [1, 9] … [7, 15]跨机器，走 InfiniBand

为什么这样排：TP 通信最重，放在变化最快的位置，保证同一个 TP 群在一台机器里；PP 只传段边界的 activation，放在最后，跨机也不怕。这就是第 8 课“TP 机内、PP 跨机”的规则，docstring 里也提醒调用方让相邻 rank 落在同一台机器上。算成员的是 RankGenerator 类；其他代码用 get_tensor_model_parallel_group()、get_data_parallel_group()、get_pipeline_model_parallel_group() 拿到群，再在群里调 NCCL。

怎么读：一个文件 15 分钟

  1. 搜 class，读每个类的 docstring，用一句话说出它解决第几课的什么问题
  2. 看 __init__ 的参数。例：ColumnParallelLinear 的 gather_output 决定要不要把切开的输出拼回来；RowParallelLinear 的 input_is_parallel 表示输入已经切好了
  3. 看 forward 调了哪个通信函数，对上前面课里数过的通信次数
  4. fusion、FP8、CUDA graph 的分支先跳过，不逐行读

先读最核心的四个，约一小时：parallel_state.py → layers.py → mappings.py → attention.py 和 mlp.py。一个坑：默认的 Transformer Engine spec 把 LayerNorm 融进了 linear_qkv（TELayerNormColumnParallelLinear），pre_mlp_layernorm 也变成了 IdentityOp。第一次读看 models/gpt/gpt_layer_specs.py 里的 get_gpt_layer_local_spec 更清楚。

带读：一层 TransformerLayer 的 forward

用 Qwen3-8B 的维度、TP = 2。Megatron 的 activation 按 [s, b, h] 排，sequence 在前。

  1. input_layernorm：每卡对完整的 [s, b, 4096] 算一遍（没开 SP 时每卡一整份）
  2. self_attention（SelfAttention）
    • linear_qkv：ColumnParallelLinear，gather_output=False。输出宽度 = Q 4096 + K 1024 + V 1024 = 6144，每卡 3072，正好是 16 个 Q head 和 4 个 KV head。f 的工作（backward 时 all-reduce input 的 gradient）在它内部完成，默认和 weight gradient 的计算 overlap（参数名 allreduce_dgrad）
    • core_attention：DotProductAttention，用 Transformer Engine 时是 TEDotProductAttention（fused 的 FlashAttention 类 kernel）。每卡只算自己的 head，不通信
    • linear_proj：RowParallelLinear，input_is_parallel=True。每卡用 [2048, 4096] 的 weight 算出部分和，再调 g（reduce_from_tensor_model_parallel_region）做 all-reduce，这是 forward 第 1 次；开了 SP 换成 reduce-scatter
  3. self_attn_bda：bias-dropout-add，加 bias、做 dropout、加 residual
  4. pre_mlp_layernorm
  5. mlp（MLP）
    • linear_fc1：ColumnParallelLinear。SwiGLU 的 gate 和 up 两个矩阵合成一个，宽度翻倍：2 × 12288 = 24576，每卡 12288
    • activation_func：SwiGLU，逐元素，在本卡算
    • linear_fc2：RowParallelLinear，每卡 [6144, 4096]，g 做 all-reduce（forward 第 2 次）
  6. mlp_bda：再加一次 residual

数一下：forward 2 次 all-reduce（linear_proj、linear_fc2 之后），backward 2 次（linear_qkv、linear_fc1 的 input gradient），和第 5 课一致。每层约 193M 个 parameter（attention 42M + MLP 151M），TP = 2 时每卡约 96M。

RL post-training：一个训练引擎，一个 inference engine

GRPO、PPO 的每一轮做两件事：rollout 用当前 policy 生成一批回答（agent 还要和环境多轮交互），主要是 decode，memory-bound（第 0 课）；training 算 reward 和 advantage，再做 gradient update，就是第 1–8 课的内容。两件事各有最合适的引擎，所以框架把两个引擎拼在一起：

  • verl：训练端 FSDP、FSDP2 或 Megatron-LM；rollout 用 vLLM、SGLang 或 HF
  • NVIDIA NeMo RL：训练端 Automodel（PyTorch 原生的 FSDP2、TP 等）或 Megatron（通过 Megatron Bridge）；生成端 vLLM、SGLang 或 Megatron 自带的 inference

为什么每轮都要重切 weight：每次 update 之后，inference engine 手里还是旧 weight，不同步的话 rollout 用的就是旧 policy。而两边切法不同。例：8 张卡，训练用 TP4 × PP2，每卡放一半的层、每层 1/4 的矩阵；vLLM 用 TP8，每卡放全部的层、每层 1/8 的矩阵。所以每个 parameter 都要先拼起来，再按新切法切开，发到对的卡上。存储格式也不同。Megatron 的 linear_qkv 按 query group 交错存（代码注释写作 q1 q2 k1 v1 | q3 q4 k2 v2 | …），HF 和 vLLM 的 Q、K、V 是分开的，所以还要重排、改名。NeMo RL 把这一步叫 refit；Megatron Core 有专门的 resharding/，README 说它主要用在 RL loop 里。

要搬多少：8B 的 bf16 weight 是 16 GB，平摊到 8 张卡每卡 2 GB，走 NVLink 约 2 ÷ 450 ≈ 4.4 ms，走 IB 约 2 ÷ 50 = 40 ms。70B 就是 140 GB，而且每轮都要搬。

colocated（同一批卡）separate（分开的卡）
怎么跑训练和 rollout 轮流用同一批卡，memory 来回腾：训练时 inference 端释放 KV cache一批卡只训练，另一批只生成
weight 怎么传不出机器：NeMo RL 用 CUDA IPC 直接共享 GPU memory跨网络：NeMo RL 默认用 NCCL broadcast
好处没有卡闲着，传得快两边能同时跑，各自选最合适的并行配置
代价同一时刻只有一边在干活一边等另一边时卡会空转；想同时跑，就要用落后几步的 policy 生成（off-policy）

30 秒英文回答

Megatron Core is NVIDIA's library of composable parallel building blocks; Megatron-LM adds reference training scripts on top, and Megatron Bridge and NeMo RL also build on it. parallel_state gives every rank TP, DP and PP coordinates. TP varies fastest, so TP groups are adjacent ranks on NVLink, and PP groups cross nodes. In a layer, linear_qkv and linear_fc1 are column-parallel, linear_proj and linear_fc2 are row-parallel: two all-reduces forward, two backward. In RL, a trainer like Megatron or FSDP alternates with an inference engine like vLLM. Their layouts differ, say TP4 × PP2 versus TP8, so after every update the weights are resharded and synced.

自测

parallel_state.py 做什么？

按 TP、PP、DP、CP、EP 的大小和 order 给每个 rank 算坐标，建好各个 process group（initialize_model_parallel），之后其他模块用 get_*_group() 取群。默认 tp 变化最快，所以 TP 群是相邻 rank，落在机内。

16 卡，TP = 2、PP = 2、DP = 4，rank 13 在哪几个群？

13 = 1 + 2 × 2 + 8 × 1，坐标 (tp 1, dp 2, pp 1)。TP 群 [12, 13]，DP 群 [9, 11, 13, 15]，PP 群 [5, 13]。

ColumnParallelLinear 在哪个文件？一层里哪些 linear 用它？

megatron/core/tensor_parallel/layers.py。linear_qkv 和 linear_fc1 用它；linear_proj 和 linear_fc2 用同一个文件里的 RowParallelLinear。f、g 在 mappings.py。

RL 为什么要 reshard weight？

每次 update 后 inference 端的 weight 就过期了，而训练端和 inference 端的切法、格式都不同（TP4 × PP2 vs TP8，QKV 交错存 vs 分开存）。所以要把新 weight 拼起来、按 inference 端的切法重切、发过去，否则 rollout 用的还是旧 policy。

Megatron Core 给了什么，是只用 PyTorch FSDP 得不到的？

FSDP 只在 DP 方向切 model state（约等于 ZeRO-3）。activation 不切，每层都要 all-gather parameter，规模大了要跨机。Megatron Core 另外提供 TP + SP（切每层的矩阵和 activation）、PP schedule（1F1B、interleaved）、CP、带 token dispatcher 的 EP、distributed optimizer、Transformer Engine 的 FP8 kernel，以及能换并行配置加载的 distributed checkpoint。70B 以上、长序列、MoE 时，缺的正是这些。
