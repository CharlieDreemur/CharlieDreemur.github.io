TP：Column / Row Parallel Linear 怎么切？
MLP 和 attention 怎么切？

先弄清楚：每个概念是什么

Tensor parallelism (TP)
把一层里的大 weight matrix 切成 \(t\) 份放到 \(t\) 张卡上，每卡只存、只算自己那份，像几个人分工填一张大表。例：\(h = 8192\)，MLP 第一层 weight 是 [8192, 32768]；\(t = 8\) 时每卡只放 [8192, 4096]。
Column parallel
weight 按列切。每卡拿完整输入 \(X\)，算出输出的几列，拼起来就是完整输出。例：\(A\) 是 [8, 32]，\(t = 2\) → 每卡 \(A_i\) 是 [8, 16]，\(Y_i = XA_i\) 是 [n, 16]。
Row parallel
weight 按行切，输入也按列切成对应的块。每卡算出的是完整形状、但只是一部分的和，要加起来才对。例：\(XB = X_1B_1 + X_2B_2\)，两项都是 [n, 8]。
All-reduce
每卡一个同形状 tensor，求和后每卡都拿到总和，详见 all-reduce。例：rank 0 有 (1, 2)、rank 1 有 (3, 4) → 两卡都变成 (4, 6)。
f / g operator
Megatron 插在并行区两头的一对通信算子。f：forward 原样传、backward all-reduce；g：forward all-reduce、backward 原样传。

看图：column / row 怎么切，MLP 怎么接

30 秒回答

Tensor parallelism splits each weight matrix across t GPUs. Column-parallel splits the output columns: every GPU sees the full input and computes a slice of the output, so the forward needs no communication, but the input gradient is a partial sum and is all-reduced in backward. Row-parallel splits the input rows: each GPU computes a full-size partial sum, so the forward needs an all-reduce. Megatron's MLP is column then row, since GeLU is elementwise and runs locally: one all-reduce forward, one backward. Attention splits by heads: QKV column-parallel, output projection row-parallel. Memory drops by t, but the all-reduces are on the critical path, so TP stays within a node.

推导 / 关键公式

\(X\) 是 [\(bs\), \(h\)]，MLP 是 \(Z = \mathrm{GeLU}(XA)\,B\)，\(A\) 是 [\(h\), \(4h\)]，\(B\) 是 [\(4h\), \(h\)]：

Column parallel（\(A\)）Row parallel（\(B\)）
每卡 weight\(A_i\)：[\(h\), \(4h/t\)]\(B_i\)：[\(4h/t\), \(h\)]
输入 → 输出完整 \(X\) → 一块列 \(XA_i\)一块列 \(Y_i\) → 部分和 \(Y_iB_i\)
forward 通信无all-reduce（g）
backward 通信dX 是部分和 → all-reduce（f）无

为什么通信位置正好相反：forward \(Y_j = \sum_k X_k A_{kj}\) 对输入维 \(k\) 求和，backward \(dX_k = \sum_j dY_j A_{kj}\) 对输出维 \(j\) 求和。哪一步的求和维度被切开了，哪一步就要 all-reduce：column 切 \(j\)，所以 backward 的 dX 是 partial sum；row 切 \(k\)，所以 forward 的输出是 partial sum。例：\(X = [1, 2]\)、\(A = [[1, 2], [3, 4]]\)、\(dY = [1, 1]\)，column 下 GPU0 算出 [1, 3]、GPU1 算出 [2, 4]，相加才是完整的 dX = [3, 7]。

MLP 为什么先 column 后 row

\[ \mathrm{GeLU}([XA_1, XA_2]) = [\mathrm{GeLU}(XA_1), \mathrm{GeLU}(XA_2)] \]

GeLU 逐元素，每卡对自己那几列直接算，结果正好是 row parallel 要的输入块，中间零通信。反过来先按行切：

\[ \mathrm{GeLU}(X_1A_1 + X_2A_2) \ne \mathrm{GeLU}(X_1A_1) + \mathrm{GeLU}(X_2A_2) \]

GeLU 之前就得 all-reduce，多一次同步。

Attention：按 head 切

\(W_Q, W_K, W_V\) 做 column parallel，每卡拿 \(a/t\) 个完整的 head，attention 在本卡算完；\(W_O\) 做 row parallel，最后 1 次 all-reduce。所以 \(a\) 要能被 \(t\) 整除。

代码（NumPy 模拟 t = 2）

rng = np.random.default_rng(0)
n, h, t = 4, 8, 2                     # n = b·s 个 token
X = rng.standard_normal((n, h))
A = rng.standard_normal((h, 4 * h))   # h → 4h
B = rng.standard_normal((4 * h, h))   # 4h → h
gelu = lambda x: x / (1 + np.exp(-1.702 * x))   # GeLU 近似
Z_ref = gelu(X @ A) @ B               # 单卡

A_cols = np.split(A, t, axis=1)       # column: 每卡 [h, 4h/t]
B_rows = np.split(B, t, axis=0)       # row:    每卡 [4h/t, h]
partial = [gelu(X @ Ai) @ Bi          # 每卡本地算，中间不通信
           for Ai, Bi in zip(A_cols, B_rows)]
print(np.allclose(sum(partial), Z_ref))     # g: all-reduce → True

# backward：column 的 dX 是 partial sum → f 做 all-reduce
dY = rng.standard_normal((n, 4 * h))
dX = sum(dYi @ Ai.T for dYi, Ai in zip(np.split(dY, t, 1), A_cols))
print(np.allclose(dX, dY @ A.T))            # True

# 反例：第一层按行切，GeLU 前必须先 all-reduce
X_cols, A_rows = np.split(X, t, 1), np.split(A, t, 0)
bad = sum(gelu(Xi @ Ai) for Xi, Ai in zip(X_cols, A_rows))
print(np.allclose(bad, gelu(X @ A)))        # False

必答点

  • Column：weight 按列切，forward 无通信；backward 的 dX 是部分和 → all-reduce
  • Row：weight 按行切、输入按列切；forward 部分和 → all-reduce；backward 无通信
  • MLP 先 column 后 row：GeLU 逐元素可本地算，forward、backward 各只 1 次 all-reduce
  • Attention：QKV 按 head 做 column，output projection 做 row
  • pros：weight、optimizer state、block 内 activation 都 /\(t\)；cons：all-reduce 在 critical path 上（限单机 NVLink），LayerNorm、dropout 仍是整份（→ SP）

追问

反过来先 row 后 column 行不行？

结果能对，但 GeLU 前要 all-reduce，GeLU 的 [\(bs\), \(4h\)] activation 每卡一整份。第二层 column 的输出又是切开的，接 residual 前还要 all-gather。all-reduce 的数据从 \(h\) 宽变成 \(4h\) 宽，再加一次 all-gather，通信量约 4.5 倍，省的 memory 也少。

bias 怎么处理？

Column 的 bias 跟着列一起切；row 的 bias 不切，all-reduce 之后加一次。要是每卡在 all-reduce 前各加一遍，bias 就被加了 \(t\) 次。

dropout 的随机数怎么处理？

TP 区域内（attention 里的 dropout）每卡用不同 seed，否则各卡的 head 拿到同一个 mask；TP 区域外（residual 前）用同一个 seed，保证各卡上的副本完全一样。

怎么验证你的实现是对的？

固定 seed，和单卡 nn.Linear 对比 output 和 gradient；\(t\) = 1、2、4，有无 bias 都测。没有多卡就用 gloo backend 在 CPU 上起多个进程。

t 越大越好吗？

不是。每卡计算按 \(1/t\) 降，通信量却不降，GEMM 变小效率下降，\(t\) 超过一台机器的 GPU 数还要走慢得多的跨机网络。见 TP 的 communication。
