RDMA 是什么、怎么用？
GPUDirect 又省掉了什么？

英文问法What is RDMA and why is it faster than TCP? · Walk me through the verbs workflow. · What does GPUDirect RDMA do? · InfiniBand vs RoCE?

考过面经：NVIDIA Research System AI 实习 2024 一面（"先问了一些基础知识，包括分布式训练，RDMA的工作流程和编程，网络的一些知识"，Pass，1p3a 1060932）

先弄清楚：每个概念是什么

RDMA
网卡直接读写对端机器的内存，对端 CPU 和 OS 都不参与。TCP 像寄快递，两边都要经过收发室（kernel）拆包、再拷进你的 buffer；RDMA 像两个仓库之间修了直达传送带。通道建好后，app 直接给网卡下单（kernel bypass），数据从 app buffer 直接上线、直接落进对端 buffer（zero copy）。
Memory registration
用之前先把 buffer 登记给网卡：pin 住页面（不被 swap，物理地址不变），把虚拟→物理地址表写进网卡，拿到 lkey / rkey。对端只有拿到 rkey 才能远程读写这块内存。
InfiniBand vs RoCE
同一套 verbs API。InfiniBand 是专用网络，链路层自带 credit-based flow control 管拥塞；RoCE 把 RDMA 跑在 Ethernet 上，要靠 PFC（Priority Flow Control）做成 lossless。iWARP 走 TCP，比 RoCE 慢。
GPUDirect 家族
P2P：同机 GPU 之间直接 copy 或 load/store，走 NVLink 或 PCIe。RDMA：网卡直接读写 GPU memory，不经 host memory 中转。Storage：NVMe / NVMe-oF 直接 DMA 进 GPU memory，省掉 CPU 的 bounce buffer。
带宽量级
显存 > NVLink > PCIe ≈ 网卡，每级差几倍到十倍。例：H100 的 NVLink 900 GB/s 约是 PCIe Gen5（128 GB/s）的 7 倍。

30 秒回答

RDMA lets a NIC read or write a remote host's memory directly. The OS sets up the connection once; after that the application posts work requests straight to the NIC, so the data path bypasses the kernel, makes no intermediate copies, and the remote CPU isn't involved. Memory must be registered first, which pins it and gives the NIC keys. InfiniBand has credit-based flow control built in; RoCE runs the same verbs over Ethernet and relies on PFC to be lossless. GPUDirect RDMA lets the NIC DMA straight to and from GPU memory over PCIe, skipping the host bounce buffer. NCCL uses NVLink inside a node and GPUDirect RDMA over InfiniBand across nodes.

关键流程

数据路径：GPUDirect RDMA 省了什么

没有 GDR：GPU memory → 拷到 host buffer → NIC → 网络 → NIC → host buffer → 拷回 GPU（两端各多一次拷贝）。

有 GDR：GPU memory → NIC → 网络 → NIC → GPU memory。前提：GPU 和 NIC 在 PCIe 拓扑上离得近，并加载 nvidia-peermem（或用 DMA-BUF）。

verbs 编程流程（NVIDIA 原题）

  1. 打开设备，分配 protection domain（PD）
  2. register memory：pin 页面，拿到 lkey / rkey
  3. 建 CQ 和 QP；带外交换 QP number、地址、rkey；QP 走 INIT → RTR → RTS
  4. post work request：send / recv，或 RDMA write / read
  5. poll CQ 拿完成事件；用完按相反顺序销毁
链路（H100 一代）每 GPU 带宽口径
HBM（H100 SXM）3.35 TB/s显存本身
NVLink 4 + NVSwitch900 GB/s双向合计，机内
PCIe Gen5 x16128 GB/s双向合计
ConnectX-7 IB NDR400 Gb/s = 50 GB/s单向，跨机；DGX H100 配 8 张，对应 8 GPU

手算例子：TP 为什么不跨机

一次 TP all-reduce 的 activation \(b\cdot s\cdot h\cdot 2\) bytes，取 \(b=1, s=4096, h=8192\)：67 MB。\(t=8\) 的 ring 每卡发 \(2\cdot\tfrac78\cdot 67\) ≈ 117 MB。

  • NVLink 单向 450 GB/s：0.26 ms；跨机 NIC 50 GB/s：2.3 ms
  • 每层 forward + backward 共 4 次，80 层：83 ms vs 752 ms → TP 放机内，跨机放 DP / PP

必答点

  • RDMA：kernel bypass + zero copy + 对端 CPU 不参与 → 低 latency、低 CPU 占用
  • 先 register memory（pin、lkey / rkey）；QP 建好后 app 直接 post WR、poll CQ
  • IB 链路层自带 credit-based flow control；RoCE = Ethernet + PFC（lossless）；同一套 verbs
  • GPUDirect：RDMA = NIC ↔ GPU memory；P2P = 机内 GPU ↔ GPU；Storage = NVMe ↔ GPU
  • 带宽：HBM > NVLink > PCIe ≈ NIC → TP 机内，DP / PP 跨机

追问

two-sided 和 one-sided 有什么区别？

send / recv 是 two-sided，对端必须先 post recv buffer；RDMA write / read 是 one-sided，对端 CPU 完全不知情，只需事先给出地址和 rkey（write with immediate 才会通知对端）。

怎么确认 GPUDirect RDMA 真的生效？

NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=NET 看选了哪种 transport（IB 还是 Socket）；查 lsmod | grep nvidia-peermem；NCCL_NET_GDR_LEVEL 决定 GPU 与 NIC 隔多远还用 GDR（PIX / PXB / PHB / SYS）。

为什么 GPU 和 NIC 要挂在同一个 PCIe switch 下？

GDR 走 PCIe peer-to-peer，绕到 CPU root complex 就慢甚至不支持。PCIe ACS 开着也会把 P2P 流量绕到 CPU，NCCL 文档说可能大幅变慢甚至 hang。

为什么注册内存要 pin？

网卡按物理地址做 DMA，页面若被 swap 或迁移，网卡就会写错地方。PyTorch DataLoader 的 pin_memory=True 也是同理。pinned host memory 才能异步 DMA 到 GPU。

没有 IB 时 NCCL 怎么办？

回退到 IP sockets（NCCL_IB_DISABLE=1 可强制），每次收发都经 kernel 和拷贝，带宽低、latency 高，多机训练会明显变慢。
