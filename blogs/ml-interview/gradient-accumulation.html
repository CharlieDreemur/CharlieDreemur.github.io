Gradient accumulation 怎么做？
为什么 PyTorch 默认累加 gradient？

英文问法Why does PyTorch accumulate gradients by default? · Implement gradient accumulation. · Is it equivalent to training with a larger batch?

考过面经：NVIDIA 框架岗 2023 onsite 第 3 轮（实现 backprop 后追问实现 grad-accumulation，知乎）· NVIDIA DL 全职 VO 2022（讨论"为什么by default grad 要累计"）

先弄清楚：每个概念是什么

.grad 累加
每次 backward() 都把新 gradient 加到 parameter 的 .grad 上，不覆盖，像存钱罐，不倒空就一直往里存。例：同一个 batch 连续 backward 两次，.grad 是一次的 2 倍。
zero_grad()
每次 optimizer step 之后把存钱罐倒空。忘了清零，这一步的 gradient 会混进上一步的。
Micro-batch 与 gradient accumulation
显存只放得下 \(b\) 个样本，却想要更大的 batch：把它拆成 \(m\) 个 micro-batch，逐个 forward + backward，gradient 攒在 .grad 里，攒满 \(m\) 个才 step 一次。像搬家一趟搬不完，分几趟搬，最后一次结账。activation memory 只按 \(b\) 算。例：\(b = 8\)，\(m = 4\)，DP 卡数 \(N = 2\) → global batch \(B = 64\)。
Loss ÷ m
每个 micro-batch 的 loss 是自己 \(b\) 个样本的 mean，\(m\) 个 gradient 直接相加会是大 batch 的 \(m\) 倍，所以每个 loss 先除以 \(m\)。
no_sync()
DDP 每次 backward 都会 all-reduce gradient。前 \(m-1\) 个 micro-batch 放进 model.no_sync()，只在本卡累加，最后一个才 all-reduce，通信次数从 \(m\) 降到 1。

30 秒回答

backward() adds into .grad instead of overwriting it. Gradients are linear, so two backward calls give the gradient of the summed loss; that makes accumulating over micro-batches or backpropagating several losses separately just work, and the price is calling zero_grad() every step. To accumulate, I split the batch into m micro-batches, divide each micro-batch loss by m, call backward on each, then step once and zero the grads. With equal-sized micro-batches that gives exactly the big-batch gradient, with activation memory for only one micro-batch. It breaks for BatchNorm, whose statistics only see the micro-batch. Under DDP I wrap the first m − 1 backwards in no_sync(), so the all-reduce runs once.

推导 / 关键公式

\(L_k\) 是第 \(k\) 个 micro-batch 的 mean loss，每个 micro-batch 都是 \(b\) 个样本：

\[ L_B = \frac1B\sum_{i=1}^{B}\ell_i = \frac1m\sum_{k=1}^{m} L_k \] \[ \nabla L_B = \sum_{k=1}^{m}\nabla\Big(\frac{L_k}{m}\Big) \]

右边就是 \(m\) 次 backward 用 += 攒出来的。不除以 \(m\)，gradient 是 \(m\) 倍，SGD 下等于 learning rate 放大 \(m\) 倍。再加上 \(N\) 张卡的 DP，global batch：

\[ B = b\cdot m\cdot N \]

手算例子

\(y = wx\)，\(w = 0\)，\(x = (1, 2, 3, 4)\)，\(y = 2x\)，loss 取 \((wx - y)^2\) 的 mean，gradient \(= \text{mean}\big(2(wx - y)x\big)\)：

  • 大 batch：\(-\tfrac{2}{4}(2 + 8 + 18 + 32) = -30\)
  • \(m = 2\)：前两个点得 \(-10\)，后两个点得 \(-50\)，直接累加 \(-60\)，多了一倍
  • 每个 loss 先 ÷ 2：\(-5 + (-25) = -30\)，和大 batch 一样

手撕代码（PyTorch + DDP）

from contextlib import nullcontext

def train_step(model, opt, micro_batches, loss_fn):
    m = len(micro_batches)
    for k, (x, y) in enumerate(micro_batches):
        last = k == m - 1
        # DDP：前 m−1 次 no_sync，只在本卡累加
        with nullcontext() if last else model.no_sync():
            loss = loss_fn(model(x), y) / m  # ÷ m
            loss.backward()                  # .grad +=
    opt.step()          # m 次 backward 后 step 一次
    opt.zero_grad()     # 清空，留给下一个 step

必答点

  • backward() 是 .grad +=：gradient 对 loss 是 linear 的，累加 = 对 loss 之和求导；代价是每步 zero_grad()
  • 做法：loss ÷ \(m\) → backward \(m\) 次 → step() → zero_grad()
  • 等价于 \(B = b\cdot m\cdot N\) 的大 batch，activation memory 只按 \(b\)
  • 不等价：BatchNorm；micro-batch 大小（或 token 数）不同
  • DDP：前 \(m-1\) 次 no_sync()，all-reduce 从 \(m\) 次降到 1 次

追问

micro-batch 大小不同（或 LLM 每个 micro-batch 的 token 数不同）怎么办？

÷ \(m\) 默认每个 micro-batch 权重一样。上例按 3 + 1 拆，得 \(-41.3\) 而不是 \(-30\)。应该用 sum 的 loss 除以整个 step 的样本数（LLM 用非 padding token 数），按大小加权就回到 \(-30\)。Hugging Face 2024 年修过 Trainer 的这个 bug。

和 BatchNorm 一起用有什么问题？

BN 的 mean / variance 只来自 \(b\) 个样本，running statistics 也按 micro-batch 更新，和真的大 batch 不一样。换 GroupNorm / LayerNorm。Transformer 用 LayerNorm / RMSNorm，不受影响（见 BatchNorm vs LayerNorm）。

加了 accumulation，learning rate 要改吗？

global batch \(B\) 不变就不用改。lr schedule 和 warmup 按 optimizer step 计数，不按 micro-batch。如果是为了把 \(B\) 变大才加 accumulation，就按新的 \(B\) 重新调 lr。

FSDP 里也用 no_sync() 吗？

可以，但 no_sync() 期间每张卡累加的是完整 gradient 而不是 gradient shard，memory 更高。是省通信还是省 memory 要权衡（见 DP / ZeRO / FSDP）。

zero_grad() 设成 None 和设成 0 有什么区别？

PyTorch 2.x 默认 set_to_none=True：省 memory，也少一次写 0。但 gradient 为 None 的 parameter，optimizer 直接跳过；gradient 为 0 时仍然会 step（比如 momentum 还会推着走）。
