DP、ZeRO-1/2/3、FSDP：每卡显存多少、通信多多少？
Megatron distributed optimizer 是哪一级？

英文问法How does DDP overlap communication with backward? · What do ZeRO stages 1, 2 and 3 shard, and how much memory per GPU? · How does torch FSDP work? · How much more communication does ZeRO-3 need than DDP?

考过NVIDIA Research Intern（"How does torch FSDP work?"，拿到 offer，Glassdoor RVW102358730，年份未核实）· 文心（"deepspeed zero1-3"）· 牛客人才库合并帖（公司未写明，"FSDP2和FSDP1的区别"）· 牛客（"DeepSpeed ZeRO stage1和stage 2的通信量区别，论文和代码实现有没有gap"）· xAI ML/Infra 第一轮补全 DP 和 FSDP 的 distributed matmul（1p3a 1171574）

先弄清楚：每个概念是什么

DDP（data parallel）
每张卡一份完整模型，各吃不同的数据，backward 后把 gradient 求平均（all-reduce），所有卡更新出同样的参数。DDP 把 gradient 分成 bucket，一个 bucket 算完就异步 all-reduce，和剩下的 backward 同时跑。
Model states：16Ψ bytes
mixed precision Adam 每个参数：bf16 param 2 + bf16 grad 2 + fp32 master、m、v 共 12 bytes（推导见 optimizer）。DDP 每张卡都存一整份，N 张卡就是 N 份重复。例：7B 模型每卡 112 GB，一张 80 GB 的卡放不下。
reduce-scatter 与 all-gather
all-reduce = reduce-scatter（求和，每卡只拿到结果的 1/N）+ all-gather（把各卡的 1/N 拼回完整的），详见 all-reduce。例：4 卡各有长 8 的 gradient，reduce-scatter 后每卡拿 2 个元素的总和，all-gather 后每卡又有完整的 8 个。
ZeRO-1 / 2 / 3
把 model states 按 DP rank 切成 N 份，每张卡只保管、只更新自己那 1/N，像合租时每人只保管一部分家当，要用再借。stage 1 切 optimizer state，2 再切 gradient，3 再切 parameter。
FSDP
PyTorch 版的 ZeRO-3：模型分成若干 unit，算到某个 unit 前 all-gather 出完整参数，算完马上释放；backward 后 reduce-scatter gradient。每卡显存 ≈ 分片后的模型 + 最大的那个 unit。

30 秒回答

In DDP every GPU holds a full replica, and gradients are all-reduced bucket by bucket during backward, overlapping communication with compute. Mixed-precision Adam needs 16 bytes per parameter, replicated on all N ranks. ZeRO shards these model states across the data-parallel ranks: stage 1 shards optimizer states, 4Ψ + 12Ψ/N bytes per GPU; stage 2 adds gradients, 2Ψ + 14Ψ/N; stage 3 adds parameters, 16Ψ/N. Stage 2 communicates 2Ψ, a reduce-scatter plus an all-gather, same as DDP, and the paper says stage 1 adds no communication either; stage 3 gathers parameters again in backward, 3Ψ or 1.5×. FSDP is PyTorch's ZeRO-3; Megatron's distributed optimizer is ZeRO-1-style optimizer-state sharding.

推导 / 关键公式

每卡 model states（bytes）

没切的部分每卡一整份，切了的部分 \(\div N\)。以 ZeRO-1 为例（ZeRO-2、3 见下表）：

\[ \text{ZeRO-1: } \underbrace{2\Psi + 2\Psi}_{\text{param, grad}} + \underbrace{\frac{12\Psi}{N}}_{\text{master, m, v}} \]

每卡通信量（元素数，ring 下再乘 \((N-1)/N\)）

DDP：all-reduce \(= \Psi + \Psi\)。ZeRO-2：gradient reduce-scatter \(\Psi\) + 更新后 param all-gather \(\Psi\)，还是 \(2\Psi\)。论文说 ZeRO-1 同样不增加通信，但没有单独推导。ZeRO-3：forward、backward 各 all-gather 一次 param，再 reduce-scatter gradient：

\[ \Psi + \Psi + \Psi = 3\Psi = 1.5 \times \text{DDP} \]

必答点

  • DDP：bucket + backward hook，all-reduce 和 backward overlap
  • 16Ψ：bf16 param 2 + grad 2 + fp32 master、m、v 12
  • ZeRO-1/2/3 依次切 optimizer state、gradient、param：\(4\Psi + 12\Psi/N\)、\(2\Psi + 14\Psi/N\)、\(16\Psi/N\)
  • 通信：DDP 是 \(2\Psi\)；ZeRO-2 是 RS + AG，也是 \(2\Psi\)；论文说 ZeRO-1 同样不增加通信；ZeRO-3 是 \(3\Psi\)（1.5×）
  • FSDP ≈ ZeRO-3（按 unit all-gather、用完释放、prefetch 下一个）；Megatron distributed optimizer ≈ ZeRO-1

追问

ZeRO-1 和 ZeRO-2 的通信量有区别吗？

论文的结论是两级都不比 DDP 多。它只推导了 ZeRO-2，gradient reduce-scatter \(\Psi\) 加 param all-gather \(\Psi\)，一共 \(2\Psi\)。ZeRO-1 单独没有推导。实现里如果 ZeRO-1 的 gradient 仍用 all-reduce，再 all-gather param，就是 \(3\Psi\)，换成 reduce-scatter 才是 \(2\Psi\)。这一句是按论文 §5.1 推算的，牛客那道题问的“论文和代码实现的 gap”指的就是这里。两级的另一个区别在显存。ZeRO-2 在 backward 中按 bucket reduce-scatter，不归自己的 gradient 用完就释放，ZeRO-1 要留一整份 gradient。

FSDP 怎么把通信藏起来？

all-gather 放在单独的 CUDA stream 上，backward 默认提前发下一个 unit 的 all-gather（prefetch）。forward 的显式 prefetch 默认关，CPU-bound 时才开。细节见 overlap。

FSDP2 和 FSDP1 有什么区别？

FSDP1 把一组参数 flatten、拼接成一个 FlatParameter 再切；FSDP2 用 DTensor 把每个参数各自按 dim-0 切。好处：表示更简单、容易和 TP 组合，sharded state dict 不需要 all-gather，也不用像 limit_all_gathers 那样阻塞 CPU。

跨机时全切太慢怎么办？

hybrid sharding：机内切（all-gather、reduce-scatter 走 NVLink），机间复制，只对各自那片 gradient 做 all-reduce。sharding factor 取 1 就是 DDP，取全部卡数就是全切。

手写 FSDP 的一层 linear 怎么写？（xAI 题）

每卡存 \(W\) 的 1/N 行。forward 前 all-gather 出完整 \(W\)，算本地 batch 的 \(XW\) 后释放。backward 再 all-gather 一次算 \(dX\)，本地算完整形状的 \(dW\)，reduce-scatter 成各自那 1/N 行。
