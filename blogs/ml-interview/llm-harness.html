LLM harness 是什么？
agent harness 和 eval harness 有什么区别？

英文问法What is an LLM harness? · What's the difference between an agent harness and an eval harness? · How do you make agent runs reproducible?

考过推断，非面经。recruiter 邮件把 "LLM Harness" 列为实习内容，但没有解释具体指什么 · 这个词在业界还没有统一定义，面试时先问清对方指哪一种

先弄清楚：每个概念是什么

Harness
模型外面的那层代码，让模型能干活、也能被测。模型像发动机，harness 是车架、方向盘和仪表盘。业界常见的说法是 Agent = Model + Harness。
Agent harness
运行时：先组装 context 再调用模型，模型要用 tool 就替它执行，同时控制 loop 和 stop，处理错误并记日志。
Eval harness
测试设施：加载一批 task，让 agent 逐个去跑，用 grader 打分，再汇总。
Grader
判断一次运行算不算成功的代码或模型，也叫 verifier。例：比较环境的最终状态和期望状态是否一致。
Trace
一次运行的完整记录：每一步的输入、输出、tool call、耗时。

30 秒回答

A harness is everything around the model that makes it usable and testable. An agent harness builds the context, calls the model, runs tools, handles errors, and logs each step. An eval harness replays a fixed set of tasks through that agent, grades each run, and aggregates the scores, so two versions can be compared. When you evaluate an agent, you measure the model and the harness together, so both must be versioned. I'd first ask which one the team means.

最小的 eval harness

def run_eval(tasks, agent, grader, k=3):
    rows = []
    for task in tasks:
        for trial in range(k):
            env = task.make_env()              # 每次从初始状态开始
            trace = agent.run(task.prompt, env)
            rows.append({
                "task": task.id,
                "trial": trial,
                "score": grader(task, env, trace),
                "steps": len(trace),
            })
    return rows

可复现：固定 model 版本和 sampling 参数。tool 返回用 mock 或 cache。每次运行都把环境重置到初始状态。prompt、tool schema、grader 全部进版本控制。每题跑 k 次，报方差。

必答点

  • harness = 模型之外让它能干活、能被测的代码
  • agent harness 是运行时，eval harness 是测试设施
  • 评 agent 时测的是 model 加 harness，两者都要有版本
  • 可复现：固定版本、mock tool、重置环境、多次运行
  • 先问清对方说的是哪一种

追问

为什么换一个 harness，同一个模型的分数会变？

context 怎么裁剪、tool 描述怎么写、出错后重试几次，都会改变结果。所以比较模型时要固定 harness，比较 harness 时要固定模型。

tool 有副作用，怎么评？

放在 sandbox 里跑，比较环境的最终状态和期望状态（state match），不看模型自己说“完成了”。

grader 用规则还是用 LLM？

能用规则就用规则：state match、exact match。开放式的回答才用 LLM judge，并且要用人工标注校准（见标注与 LLM judge）。

trace 里要记什么？

每一步的 input 和 output，tool call 和它的返回，再加 token 数、latency 和错误。有了它才能回答“为什么失败”，并把失败分类统计。
