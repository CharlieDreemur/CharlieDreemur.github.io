考过推断，没有 Unity 来源的面经，别家面经里也没有直接问这题的 · 依据是公开材料：Meta KernelEvolve、AlphaEvolve、Unity Vector 自己的 FlashVector 论文，以及 Unity Q3 2026 earnings call 的第三方文字稿 · 很少单独问，主要是回答 "why Unity" 的素材

先弄清楚：每个概念是什么

GPU-hour
用了几张 GPU 乘以多少小时，GPU 的成本按它算。100 张卡跑 10 小时是 1000 GPU-hour。
Batch inference
离线对一大批数据跑模型。没有用户在等结果，所以只看总共多久跑完。
Throughput
每秒处理多少样本。offline 只看它，serving 还要同时守住 latency SLO。
时间占比
这个 kernel 占整个 job 的 GPU time 的比例。kernel 快了能省多少，要先乘上它（见 Amdahl's law）。
Production trace
从生产里录下来的真实输入。kernel 该对哪些 shape 优化，从它里面统计。

看图：kernel 快一点，怎么变成成本

30 秒回答

Ads models are retrained and run batch inference every day, so a faster kernel turns directly into fewer GPU-hours. There are production numbers. Meta's KernelEvolve raised inference throughput of its Andromeda ads model by over 60%, and AlphaEvolve cut Gemini's training time by 1%. Unity's own FlashVector reports 1.1 to 2 times higher throughput on six production models. Offline, I'd optimize throughput rather than request latency, take shapes from production traces, gate every kernel swap with regression tests, and re-tune when the GPU generation changes. The gain is the kernel's share of the job times its speedup, so I'd profile first.

四条证据，各自能说明什么

来源数字或原话能说明什么
Meta KernelEvolve（2026-04 的 blog）Andromeda 广告模型的 inference throughput 提升 60% 以上；MTIA 上一个广告模型的训练 throughput 提升 25% 以上。都是自报baseline 已经用了 torch.compile 和厂商库，广告模型的 kernel 仍有空间，训练侧也有
AlphaEvolve（DeepMind，2025-05）matmul 的 tiling heuristic 让 kernel 平均快 23%，Gemini 的训练时间少 1%kernel 的 23% 到整个训练只剩 1%，时间占比决定收益
FlashVector（Unity Vector，2026-09）6 个生产模型的 latency speedup 是 1.30–1.98×，throughput 是 1.10–2.00×Unity 自己在做，范围是整个 serving stack。摘要原话 "Model serving is one of the largest cost drivers in production recommender systems"
Unity Q3 2026 earnings call（2026-11-05，第三方文字稿）CFO 说 Vector 超预期靠三件事，其中一件是 "Major advancements in infrastructure efficiency"管理层点名了 infrastructure efficiency。call 里没有提 agent，把它归因于 FlashVector 是推断

前三条讲的都是 serving 或别家的训练。Unity 的 offline 训练和 batch inference 用多少 GPU-hour，没有公开数字。

搬到 offline，有四个特点

  • 目标是 throughput：没有单次请求的 latency SLO，看 samples/s 和 GPU-hour
  • shape 取自 production trace：AlphaEvolve 从 kernel 的用户那里收集真实 shape，一半用来搜索，一半留作评测
  • 换 kernel 前过回归测试：先对 reference 查正确性，再看 job 的提升（见 kernel 正确性）
  • 换代 GPU 要重新优化：KernelEvolve 同时覆盖 NVIDIA、AMD、MTIA 和 CPU

手算一遍，数字是示意。一个每天跑的 batch inference job 用 1000 GPU-hour，某个 kernel 占 GPU time 的 30%。把它做快 2 倍，这一段从 300 降到 150，整个 job 少 15%，每天省 150 GPU-hour。同一个 kernel 如果只占 3%，快 2 倍只省 1.5%，很可能分不出它和噪声。

怎么把 profile、diagnose、optimize、verify 的循环搬到 data 和 training pipeline，见 offline pipeline 优化。

必答点

  • 广告模型每天训练、跑 batch inference，kernel 快了直接省 GPU-hour
  • 别家的生产数字：Meta KernelEvolve 60% 以上，AlphaEvolve 训练时间少 1%
  • Unity 自己的数字：FlashVector 6 个生产模型 throughput 1.10–2.00×
  • 收益等于时间占比乘以提速，所以先 profile 看占比
  • offline 看 throughput 和 GPU-hour；shape 取自 production trace；换 kernel 前过回归测试；换代 GPU 重新优化
  • earnings call 那句不能说成 FlashVector 的功劳

追问

怎么用它回答 "why Unity"？

可以说 "FlashVector already runs this loop in production on serving. I'd like to bring the same loop to offline training and data pipelines, where it saves GPU-hours every day, and I've designed verifiers for RL environments, which is the hard part of that loop." 公开材料没写 Offline 组已经在做这件事，所以用 I'd like to，不要说成 you already。

为什么 kernel 快 23%，训练时间只少 1%？

因为这些 kernel 只占训练时间的一小部分。按 1% ÷ 23% 粗算，占比大约是 4% 到 5%。这个占比是推算，论文没有给。

kernel 快了，GPU-hour 一定省吗？

不一定。GPU 在等 CPU 准备数据时，kernel 再快，一步的时间也不变（见 瓶颈会转移）。省下的时间还要超过 noise floor 才算数。

Offline 组和 kernel 有直接的证据吗？

只有一条 JD 线索。一个已关闭的旧版 Offline 岗在要求里列了 "Torch Compilation, Quantization, CUDA, GPU kernel optimization"。本岗的 JD 没有写 kernel 或 agent。

Earnings call 那句话，面试里能怎么用？

可以说管理层把 infrastructure efficiency 列为 Vector 增长的原因之一，CFO 还说 gross margin 的提高主要来自 cloud costs 上的 leverage。不能说这是 agent 或 FlashVector 带来的，call 里没有这样讲。
