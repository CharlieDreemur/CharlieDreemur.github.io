BERT 和 GPT 有什么区别？
为什么现在的 LLM 都是 decoder-only？

英文问法Compare BERT and GPT. · How is BERT pre-trained? · Why are modern LLMs decoder-only?

考过面经：MAI Senior L63 第 3 轮（BERT vs GPT architecture and differences）· NVIDIA 框架岗 2023 onsite 第 2 轮：BERT 是什么、怎么训练、怎么做 doc embedding，接着问双塔检索的训练、loss 和 inference（知乎）

先弄清楚：每个概念是什么

Bidirectional vs causal mask
BERT 像做阅读理解，每个词左右都能看；GPT 像接龙，每个词只能看自己和左边，右边被 causal mask 遮住。例：「我 爱 吃 苹果」，BERT 的「吃」看 4 个词，GPT 的「吃」只看「我 爱 吃」。
Encoder-only / decoder-only
两者的 block 几乎一样，差别就在 mask：不遮是 encoder（BERT），遮住右边是 decoder（GPT），后者能一个个往后生成。
MLM（masked language modeling）
完形填空：随机挑 15% 的 token 让模型猜。挑中的 80% 换成 [MASK]、10% 换随机词、10% 不变。例：1000 个 token 只有 150 个算 loss。
Next-token prediction
看前面所有词猜下一个，每个位置都是一道题。生成时把猜出的词接上再猜（autoregressive）。例：1000 个 token 约 1000 个都算 loss。
Fine-tuning vs in-context learning
BERT 要接一个 task head 用标注数据 fine-tune；GPT-3 把几个例子写进 prompt（few-shot），不更新 weight 就能做新任务。

30 秒回答

BERT is an encoder-only Transformer with bidirectional self-attention, pre-trained with masked language modeling: mask 15% of tokens and predict them from both sides. GPT is decoder-only with a causal mask and is trained to predict the next token. So BERT gives strong representations for understanding tasks like classification, NER and retrieval embeddings, usually after fine-tuning, while GPT generates text naturally and, at scale, does few-shot in-context learning. LLMs converged on decoder-only because the objective matches generation, every token gives a training signal instead of 15%, any task can be phrased as text continuation, and the causal mask lets us reuse a KV cache.

推导 / 关键公式

BERT 只在被 mask 的位置 \(\mathcal{M}\)（约 15%）算 loss：

\[ \mathcal{L}_{\text{MLM}} = -\sum_{i\in\mathcal{M}} \log p(x_i \mid x_{\setminus\mathcal{M}}) \]

GPT 每个位置都算：

\[ \mathcal{L}_{\text{LM}} = -\sum_{t=1}^{T} \log p(x_t \mid x_{<t}) \]

两者只差 attention 里加不加 causal mask：

\[ \mathrm{softmax}\Big(\frac{QK^\top}{\sqrt{d_k}} + M\Big),\quad M_{ij} = -\infty \ \text{if}\ j > i \]

BERT 为什么不直接用 next-token：双向时每个词能间接"看到自己"，只能先遮掉再猜。

为什么 LLM 都是 decoder-only

  1. objective 就是生成：pre-training 和 inference 同一个格式，任何任务都能写成续写（GPT-2 zero-shot，GPT-3 few-shot）。
  2. 信号密：每个 token 都是 target；BERT 每批只预测 15%，收敛更慢。
  3. 推理便宜：causal 下前面 token 的 K、V 不会被后来的 token 改变，可以 KV cache；双向模型每加一个词，前面全部要重算。
  4. 实验：只做无监督 pre-training 时，causal decoder-only 的 zero-shot 最好；但之后还要 fine-tune 的话，双向 + MLM 的模型更强。

必答点

  • BERT：encoder-only、bidirectional、MLM（15%，80/10/10）
  • GPT：decoder-only、causal mask、next-token prediction
  • BERT 擅长理解 + fine-tune；GPT 擅长生成 + in-context learning
  • decoder-only 赢在：objective = 生成、每个 token 都有 loss、KV cache、zero / few-shot

追问

为什么 80/10/10，不全换成 [MASK]？

fine-tuning 时没有 [MASK]，全换会造成 pre-train / fine-tune mismatch。模型也不知道哪个词被换过，只能给每个 token 都保留好的上下文表示。

NSP 有用吗？

BERT 原文说对 QA、NLI 有帮助；RoBERTa 发现去掉 NSP 持平或略好，之后的模型基本不用。

BERT 怎么做 doc embedding 和双塔检索？（NVIDIA 原题）

query、doc 各用一个 BERT 编码，取 [CLS] 向量，相似度是 dot product。用 in-batch negatives 训练，loss 是正例对所有候选的 softmax cross-entropy（DPR）。inference 时 doc 向量离线算好建 FAISS index，线上只编码 query 再做 ANN。没 fine-tune 的 [CLS] 不是好的句向量。流程见 RAG。

BERT 能生成文本吗？

不自然。MLM 不是从左到右的分解，没法一个个往后接，硬做要反复 mask 再预测，效果和效率都不如 decoder。

T5 这种 encoder-decoder 呢？

encoder 双向读输入，decoder 带 causal mask 生成并 cross-attend encoder。objective 是 span corruption：连续被遮的一段换成一个 sentinel，decoder 只输出被遮的片段。适合翻译、摘要这类 input → output 任务。
